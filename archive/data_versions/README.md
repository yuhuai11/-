# 数据版本封存中心

本目录用于统一登记工程中已经产生、使用或淘汰的数据版本。为避免破坏配置文件、实验脚本、审计哈希和历史结果的复现路径，数据文件**不做物理迁移**；“封存”通过集中登记、原目录状态标记和关键元数据校验实现。

## 分类

- `historical_internal/`：已被替代的 DADS 内部数据版本，只允许复现、审计和消融。
- `current_internal/`：当前修正后的内部训练/验证/测试基线。
- `consumed_external/`：已用于开发、调参或结果报告的外部数据，不再是全新的独立测试集。
- `future_final_holdout/`：未来独立最终测试集的准入规则；当前没有录音数据。

完整状态见 [DATASET_REGISTRY.csv](DATASET_REGISTRY.csv)，关键登记文件的哈希见 [METADATA_CHECKSUMS.sha256](METADATA_CHECKSUMS.sha256)。

## 状态含义

- `ACTIVE_INTERNAL_BASELINE`：当前内部基线，可以继续训练、验证和内部测试。
- `FROZEN_SOURCE`：保留的原始来源，只能按已记录协议生成数据。
- `SEALED_SUPERSEDED`：已经被新方案替代，不得用于新的主结果。
- `SEALED_INTERMEDIATE`：历史中间版本，只能用于审计或消融。
- `SEALED_CONSUMED_*`：已经参与开发或评估，不得重新包装为“未见最终测试集”。
- `EMPTY_LOCKED_INTAKE`：未来数据入口为空，只有满足准入规则后才能放入数据。

这里的 `SEALED` 是实验管理状态，不代表操作系统层面的只读权限。

## 使用纪律

1. 所有论文表格必须注明数据集 ID、状态、划分单位和是否参与过阈值/模型选择。
2. 历史数据可以复现实验，但不得与当前基线混合后继续沿用旧实验名称。
3. 已使用外部数据只能作为历史对比、误差分析或开发数据，不能承担新的最终泛化结论。
4. 新外部数据必须先登记、去重并冻结模型和阈值，再进行一次性最终评估。

运行 `bash scripts/verify_data_archive.sh` 可检查关键元数据是否被修改以及未来测试集入口是否仍为空。
