# G16多SNR受约束训练方案

## 1. 研究结论与动机

G15-P3b未达到原始G14 tune F1晋级门限，但P4仅tune配对诊断显示，P3b相对G7在
−15、−10、−5和0 dB的平均配对lift与排序准确率均显著提高，背景FPR下降，跨SNR
单调率提高。固定阈值TPR略降，说明单一−10 dB配对训练改善了判别间隔，但没有直接
覆盖完整SNR曲线。

G16首先验证一个单变量假设：保持模型、数据、监督损失、蒸馏、学习率和安全门不变，
只把配对目标从单一−10 dB改为四档共享增益多SNR。

## 2. P1多SNR训练路径预检

每个batch继续使用G15-P3b锁定的来源组成：

| 来源 | 条数 |
|---|---:|
| DADS回放 | 60（30正、30负） |
| G9机械困难负样本 | 4（四类各1） |
| Kielce UAV | 32 |
| TAU背景 | 32 |

32组Kielce/TAU基础配对各自同时生成−15、−10、−5和0 dB条件，因此每个训练batch
额外包含128个正配对和128个背景负配对。一个基础配对的四档条件使用最坏情况下的
唯一共享防削波增益，保证四档负样本逐样本完全相同。配对排序损失仍使用margin 0.5
和权重0.25，四档等权；−10 dB条件数量仍为32，不因扩展SNR而减少。

P1只执行一个固定batch的前向和反向，用于验证：

- 四档各32个条件，SNR、RMS、峰值和共享背景身份全部满足约束；
- 冻结G7教师与学生初始化一致；
- 学生仍只有2,049个二分类头参数可训练；
- 监督、蒸馏、四档配对及总损失有限；
- AMP反向梯度有限，显存适合RTX 3080；
- 不执行optimizer step、不写检查点、不启动正式训练；
- 不读取历史DADS已消费内部回归集（原`test`）、G9 guard、G14 dev_holdout或G13。

服务器命令：

```bash
cd /home/user1/JJZ/ABDDV-CRNN
bash scripts/run_g16_p1_multisnr_preflight.sh \
  2>&1 | tee logs/g16_p1_multisnr_preflight.log
```

只有P1通过后，才实现正式训练、配对开发指标和预注册检查点选择规则。

## 4. P2正式训练与预注册选择门限

P2仍从只读G7 seed42初始化，不继承P3b权重；训练数据、batch组成、监督损失、冻结
教师蒸馏、学习率`5e-5`、最多10轮和patience 3均保持不变。每个训练batch的32组
Kielce/TAU配对扩展为四档共享增益条件，四档等权进入margin ranking loss。

每轮只读取已锁定的DADS validation、原始G14 tune以及G14-D tune配对。检查点必须
同时满足：

1. DADS validation F1相对G7下降不超过0.003；
2. 原始G14 tune F1相对G7下降不超过0.001；
3. 四档SNR各自的平均lift增量均不低于0.005；
4. 四档SNR各自的排序准确率均不低于G7；
5. 四档背景FPR均不高于G7；
6. 跨SNR单调率相对G7至少提高0.02；
7. −15和−10 dB正类TPR相对G7下降均不超过0.005。

第7项专门阻止模型通过整体下移概率、牺牲低SNR灵敏度来降低背景误报。只有七项全部
通过才写入`best.pt`；合格候选之间最大化四档中最弱的mean lift增量。早停在DADS和
原始G14安全的前提下跟踪该最弱SNR lift，持续改善时不会累计patience。

正式训练前先运行选择预检。该预检只计算冻结G7在两类开发集合上的基线和锁定门限，
不做反向、不执行optimizer step、不写检查点：

```bash
cd /home/user1/JJZ/ABDDV-CRNN
bash scripts/run_g16_p2_seed42.sh preflight \
  2>&1 | tee logs/g16_p2_selection_preflight.log
```

预检通过后才能运行seed42。历史DADS已消费内部回归集（原`test`）、G9 guard、
G14 dev_holdout、G13和最终外部数据继续保持关闭。
