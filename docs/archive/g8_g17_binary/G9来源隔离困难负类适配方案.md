# G9：来源隔离困难负类适配方案

## 1. 研究问题与证据边界

G7 在同结构对照下证明 AudioSet 预训练产生了真实的 OOD 排序收益：
PANNs-PT 相对 PANNs-Scratch 的 `val_ood` holdout ROC-AUC 提高 0.04741，
标准化 `pAUC@FPR≤0.05` 提高 0.04138。但 G7 根据 tune 冻结的 1%/5%
阈值迁移到 holdout 后，实际 FPR 为 3.7685%/9.0175%，未通过
2%/7.5% 上限。

G8 使用来源块保守阈值后，1% 工作点的 FPR 降至 2.4226%，但 TPR
降至 17.9452%；5% 工作点的 FPR 降至 2.8264%，TPR 仅 18.9041%。
因此仅提高阈值不能同时保持低误报和召回。

G8 已在 holdout 中定位到 `HELICOPTER_013.wav` 等困难背景。这使
“周期机械困难负类”成为合理的开发假设，但也意味着现有 holdout 已被
反馈给方案设计。从 G9 开始：

- `val_ood holdout` 永久降级为已查看的开发诊断集，不再用于选模型、
  选损失、选采样比例或回调阈值；
- 现有 `Unseen` 与 `Real-world` 已为旧模型生成完整预测与报告，
  也不得再宣称为全新无偏确认集；
- G9 准备阶段可以只为重复/来源隔离审计读取 `val_ood` manifest 与音频
  SHA256，但不读取预测、不计算指标、不训练且不选阈值；正式训练阶段不读取
  `val_ood` 任何内容。Unseen/Real-world 及其 manifest/预测继续完全禁止；
- 最终泛化结论必须使用另外采集、原始来源隔离且从未查看的确认集。

G9 的可验证假设是：在保持 G7-PT 架构、AudioSet 初始化、DADS 数据、
声学增强和优化方法不变时，仅加入来源隔离的周期机械困难负类，
能否改善 ROC 左端排序，而不是只平移 logit 或牺牲 UAV 召回。

## 2. 阶段1的单变量定义

阶段1候选命名为 `G9-HN-BCE`，与 `G7-PT seed 42` 比较时只允许一项
实质变化：在 DADS train 中追加 ESC-50 周期机械困难负类。

冻结项：

- PANNs `Cnn14_16k` 结构与官方 AudioSet checkpoint；
- G7-PT 的前端、FP32/AMP 边界、batch size 128、Adam、学习率、早停和 seed 42；
- G7-PT 的 G2 波形增强参数；
- `BCEWithLogitsLoss(pos_weight=auto)`；
- DataLoader 使用普通确定性 shuffle，不开启来源或类别重采样；
- DADS val及历史DADS已消费内部回归集不追加困难负类，checkpoint仍只根据DADS val F1选择。

阶段1不引入非对称损失、focal loss、hard-negative mining、动态过采样、
额外温度拟合或新阈值算法。这些因素若后续需要测试，必须建立新的
单因素消融，不得在 G9-HN-BCE 中同时改变。

## 3. 困难负类与来源级划分

### 3.1 阶段1类别

ESC-50 类别号固定为：

| 类别号 | 类别 |
|---:|---|
| 35 | washing machine |
| 36 | vacuum cleaner |
| 40 | helicopter |
| 41 | chainsaw |
| 44 | engine |
| 47 | airplane |

选择的是可能与无人机共享谐波、旋转或稳态机械频谱的多类背景，
不是从 G8 holdout 复制失败音频。

ESC-50 官方仓库声明：完整 ESC-50 使用 CC BY-NC，只有 ESC-10 子集使用
CC BY。G9 选的六类不属于 ESC-10，因此阶段1仅限非商业研究；必须保留
每个 clip 的 attribution，并引用 Piczak (2015)。当前候选 WAV 由 GitHub U16
仓库转存/分段，还需要将每个本地文件追溯到官方 ESC-50 clip，并补齐当前本地
数据副本缺失的 LICENSE/attribution 文件。官方 CC BY-NC 许可已核验，所以
`publication_ready=false` 不阻断本地非商业科研的 prepare/preflight/train；它必须阻止
数据、cache、模型对外发布和论文定稿。发布前必须恢复逐 clip attribution/LICENSE、
引用 Piczak (2015)，且禁止商业用途。ESC-50 官方还
提醒原始录音可能存在与类别相关的预处理或带限；因此 G9 可能学到数据集
捷径，必须通过新录制的来源隔离确认集验证，不得把 ESC-50 内部收益直接
解释为真实环境泛化。

### 3.2 文件名和原始源组

本地 U16 派生文件名使用
`<fold>-<clip_id>-<take>-<class_id*10+segment_index>.wav`。例如末位 `360`–`364`
表示 ESC-50 类别36的五个分段。解析后字段固定为：

- `esc_fold`：官方 fold 1–5；
- `class_id = encoded_index // 10`，`segment_index = encoded_index % 10`；
- `recording_group = fold-clip_id-take-class_id`：一个本地5段录音；
- `source_group = fold-clip_id`：原 Freesound provenance，合并 A/B/C/D take。

官方 ESC-50 已按原始来源给出5折。G9 不根据处理后文件名重新随机分组，
而是固定使用 fold 1–4 作为 train、fold 5 作为 guard；对每个类别在
`recording_group` 层应得到32个 train 和8个 guard 录音。split 归属和交叉门控以
`source_group`为准；不允许将同一 `clip_id` 的 A/B take 分到两侧。必须先分源
再处理音频，保证：

- train/guard `source_group` 交集为零；
- train/guard SHA256 交集为零；
- ESC-50 与 DADS 全部 split 的 SHA256 交集为零；
- ESC-50 与 `val_ood` tune/holdout 的路径标识、生成样本 SHA256 和原始来源
  SHA256 交集为零；
- Unseen/Real-world 及其 manifest 不被打开，因而本阶段不虚构对这两个锁定集
  已计算出“零交叉”；训练入口通过路径别名拒绝保持隔离，最终发布前再由独立
  封存注册表或新的确认集执行不泄露内容的交叉审计；
- 输入中任一软链接解析到锁定路径时立即失败。

guard 只用于数据完整性和后续开发保护，不追加到 DADS manifest，不进入
训练、自动 `pos_weight` 或背景 mixer。

### 3.3 音频与失败关闭审计

准备入口必须拒绝：

- 非 WAV、不能解码、非有限值、静音或时长不合法的文件；
- 非二元整数标签，或困难负类标签不是 0；
- 重复 SHA256、同源跨 split、输出已存在覆盖；
- 候选池、DADS 输入、训练清单或输出中任一 `unseen`/`real_world` 等锁定集
  名称变体或软链接绕过；只有配置中预注册的 `val_ood` tune/holdout 可在
  prepare 阶段用于身份与重复审计，绝不进入合并训练清单；
- manifest 与当前音频、DADS manifest 或配置 SHA256 不一致。

处理后的 HN train 波形作为独立负类训练样本。它们不得进入 G2
“正类+背景” mixer 的背景采样池，否则“追加负类”同时变成“改变正类
混音分布”，破坏单变量因果对照。旧 DADS manifest 不含 `dataset_origin`
等 G9 列时，Dataset 必须继续使用全部 DADS train 负类作为 mixer，保持 G7
回归行为。

## 4. 不可变 manifest 与产物

准备命令的显式输入为：

```text
configs/g9_hard_negative_data.yaml
artifacts_full/manifests/dads_all_seed42.csv
```

产物固定为：

```text
artifacts/g9_hard_negatives/
├── audit.json
├── manifests/
│   ├── hn_train.csv
│   ├── hn_guard.csv
│   └── dads_g9_hn_seed42.csv
└── cache/
    ├── train/
    └── guard/
```

`audit.json` 必须至少绑定：

- 数据配置 SHA256；
- 原 DADS manifest SHA256；
- `hn_train.csv` 和 `hn_guard.csv` SHA256；
- 合并后 `dads_g9_hn_seed42.csv` SHA256；
- 每类样本数、源组数、train/guard 数量；
- 样本/source_group/SHA256 交集审计；
- `locked_datasets_read: []`。

正式训练必须在加载音频和初始化 GPU 前重新计算上述输入 SHA256，
并与 audit 严格相等。检查点与 audit 不匹配时禁止 `--resume`；阶段1也
禁止使用 G7 的 `last.pt` 或缺少 G9 manifest/audit 绑定的任何 checkpoint 恢复。

## 5. 门控和停止规则

### 5.1 运行前门控

只有以下条件全部满足才能训练：

1. 配置 delta 审计证明 G9 相对 G7-PT 只变更 HN 数据接入、产物路径及
   必要的 manifest/audit 绑定；
2. 损失仍为普通 BCE，无 `sampling` 配置，DataLoader 使用 natural shuffle；
3. 所有数据审计、锁定集拒绝和 hash 绑定通过；
4. 真实 GPU preflight 返回 `passed: true`，logit/loss 全部有限；
5. 输出 `seed_42` 目录不存在或为空，不覆盖 G7/G8 产物。

任一条失败即停止，不自动降级为旧 manifest，不跳过审计继续训练。

### 5.2 历史DADS已消费内部回归非劣

本节使用的是历史`dads_all_seed42.csv`的原`test`划分。历史流程先在每个标签内
随机把Parquet行（`AudioRef`）分配到Train、Validation和Test，再把每行展开成1秒
片段；同一行的片段不跨split，但`source_path`不是实际分组键，其零交集只是事后
身份审计结果。后验原始WAV字节级SHA256审计发现15个重复哈希组，共涉及30条Parquet
记录；每组保留1条并移除15条，其中6组成员原本跨至少两个split，连带移除244条历史
1秒manifest片段。

DADS还缺少会话、设备、场景和无人机型号元数据。该Test已被G9及其他候选门禁读取，
故它是“历史DADS同数据源已消费内部回归集”，不能作为来源隔离的独立泛化证据。旧
`dads_dedup_v2`只去除原始WAV字节级精确重复，仍保留历史1秒
`loop/tail_loop`预处理和标签相关时长/重复捷径。后续主实验应改用
`dads_native_half_second_content_component_v2`原生0.5秒内容组件隔离协议。G9名称
中的“来源隔离”仅指新增ESC-50困难负类与既有数据之间以及HN train/guard之间的
预注册隔离。

使用冻结的 0.50 阈值。G9 必须先满足 G7 相对 G2 的硬保护线：

| 指标 | 最低值 |
|---|---:|
| 历史DADS已消费内部回归F1 | 0.9932216423 |
| 历史DADS已消费内部回归Recall | 0.9916732302 |
| 历史DADS已消费内部回归Specificity | 0.9908403856 |

同时建议保护直接父模型 G7-PT，使用相同容差后的综合更严门槛为：

| 指标 | 综合最低值 |
|---|---:|
| 历史DADS已消费内部回归F1 | 0.9949923709 |
| 历史DADS已消费内部回归Recall | 0.9955672826 |
| 历史DADS已消费内部回归Specificity | 0.9908403856 |

checkpoint早停不根据该历史回归集选择，但它实际用于候选门禁，因而已经消费。
内部回归门控失败时立即停止，不运行`val_ood`，不改阈值挽救，不扩展seed 43/44。

### 5.3 低 FPR 开发门控

现有 holdout 不参与阶段1自动流程。历史DADS内部回归门控通过后，另行冻结
`val_ood tune` 的来源级开发协议：可使用固定的5折 `uav_source`/
`background_source` 交叉验证，每折只在其余负类源拟合阈值，并在未参与
拟合的来源上评价。

预注册发展门槛不得低于 G7：

- 1% 工作点实际 FPR ≤ 0.020，TPR ≥ 0.10；
- 5% 工作点实际 FPR ≤ 0.075，TPR ≥ 0.30；
- ROC-AUC 相对 G7-PT 非劣容差不超过 0.01；
- `pAUC@FPR≤0.05` 不低于 G7-PT，且来源成组 bootstrap 支持正向改善；
- 至少一个低 FPR 工作点的 TPR 相对 G7-PT 实质提高 0.05，另一工作点
  不得反向；
- 背景来源 macro/p90 FPR 不得恶化超过 0.02。

通过 seed 42 开发门控后才可以扩展 43/44，并要求至少 2/3 seed 同方向。
本门控仍只是开发证据，不是最终无偏确认。

### 5.4 新确认集要求

所有 G9 候选、seed 聚合方式、checkpoint、预处理和阈值算法冻结后，必须
建立全新的 `confirm_cal` 和 `confirm_test`：

- 两者按原始录音/视频ID、设备、地点、日期和会话物理隔离；
- 与 DADS、G9-HN、val_ood、旧 Unseen/Real-world 同时执行 SHA256、来源ID和
  声学近重复审计；
- `confirm_cal` 只使用负类冻结 1%/5% 阈值；`confirm_test` 在阈值冻结后
  只读一次；
- 1% FPR 确认建议至少 3,000–10,000 个非重叠1秒负类片段，且不少于
  约150个独立原始录音块；
- 主结论使用来源成组的单侧95%置信界，不把同一录音的重叠窗视为独立
  样本。

确认失败时 G9 不晋级。任何后续调整必须作为 G10 并准备另一套确认集，
不得在同一 `confirm_test` 上反复迭代。

## 6. 服务器阶段1命令

阶段1脚本不包含任何 holdout、Unseen 或 Real-world 模型评估。prepare 只能
对 `val_ood` manifest 与音频执行身份/hash 隔离审计，不可加载历史预测或计算模型指标。
首先在服务器审计
准备阶段：

```bash
cd /home/user1/JJZ/ABDDV-CRNN
bash scripts/run_g9_hn_stage1.sh prepare \
  2>&1 | tee logs/g9_hn_stage1_prepare.log
```

检查 `audit.json` 的 hash 绑定、零交叉和 `locked_datasets_read: []`，再运行不写正式
checkpoint 的 GPU 预检：

```bash
bash scripts/run_g9_hn_stage1.sh preflight \
  2>&1 | tee logs/g9_hn_stage1_preflight.log
```

只有 preflight 显示 `passed: true` 时才在后台启动 seed 42：

```bash
nohup bash scripts/run_g9_hn_stage1.sh train \
  > logs/g9_hn_stage1_seed42.log 2>&1 &
echo $! | tee logs/g9_hn_stage1_seed42.pid
```

稳定查看进度：

```bash
watch -n 5 'PID=$(cat logs/g9_hn_stage1_seed42.pid 2>/dev/null); \
ps -p "$PID" -o pid,etime,%cpu,%mem,stat,cmd --no-headers; \
nvidia-smi --query-gpu=temperature.gpu,utilization.gpu,memory.used,memory.total,power.draw \
  --format=csv,noheader; \
tr "\r" "\n" < logs/g9_hn_stage1_seed42.log | tail -n 12'
```

阶段1完成后先执行历史DADS内部回归门控。在门控结果明确之前，不运行任何
`val_ood` 或外部测试命令。
