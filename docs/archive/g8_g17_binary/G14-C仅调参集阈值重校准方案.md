# G14-C仅调参集阈值重校准方案

## 1. 背景

G14-B表明G14-A在阈值0.5下不能替代G7：DADS F1下降约0.011，G9 guard误报率
由0.0625升至0.1333至0.1375。但DADS AUC只下降约0.00009，val_ood排序能力反而
提高，符合“分类分数整体向正类偏移”的校准问题特征。

G14-C冻结全部模型参数，只允许选择一个供三个seed共同使用的阈值。该阶段不是新一轮
训练，也不允许放宽G14-B门槛。

## 2. 阈值拟合范围

拟合阶段只可读取：

- DADS val及锁定G7的val预测；
- val_ood tune及锁定G7的tune预测；
- G14 tune及三个G14-A seed的预测。

禁止读取历史DADS已消费内部回归集（原`test`）、val_ood holdout、G9 guard和G13
封存数据。尽管前三个开发留出集已经在G14-B中观察过，代码仍将fit与evaluate物理
分离；因此G14-C结果只能作为开发证据，不能冒充全新最终测试。

## 3. 预注册选择规则

在0.50至0.95之间以0.01步长搜索。每个候选阈值必须让三个seed同时满足：

- DADS val F1相对G7下降不超过0.005；
- DADS val特异性相对G7下降不超过0.005；
- val_ood tune F1不低于G7；
- G14 tune F1不低于0.995。

选择满足全部条件的最低共享阈值，以尽量保留召回率。若不存在可行阈值，则不读取
holdout，直接终止G14-A路线。

## 4. 执行顺序

先只拟合并封存阈值：

```bash
cd /home/user1/JJZ/ABDDV-CRNN
mkdir -p logs

nohup bash scripts/run_g14_c_threshold.sh fit \
  > logs/g14_c_threshold_fit.log 2>&1 &
echo $!
```

完成后检查：

```bash
cat artifacts/g14_domain_generalization/threshold_recalibration/calibration.json
```

只有`passed: true`且`holdout_inputs_read: []`时，才执行一次留出评估：

```bash
bash scripts/run_g14_c_threshold.sh evaluate \
  2>&1 | tee logs/g14_c_threshold_evaluate.log
```

最终仍使用G14-B原门槛。通过时只允许进入数据集标签反事实控制，不能直接晋升；
失败时终止仅分类头适配路线。

## 5. 正式拟合结果

拟合完整搜索了0.50至0.95的46个共享阈值，但没有可行解：

- 三个seed的DADS val F1约束在0.67至0.95均可满足；
- DADS val特异性约束要求阈值不低于0.78；
- val_ood tune F1不低于G7的约束要求阈值不高于0.74；
- G14 tune F1约束在0.50至0.94均可满足。

因此DADS特异性与val_ood F1的可行区间不存在交集。这不是阈值步长或单个seed随机
波动造成的。`calibration.json`记录`passed: false`、`selected_threshold: null`、
`holdout_inputs_read: []`；按预注册规则不执行evaluate，正式终止G14-A仅分类头
适配路线。

下一阶段回到数据级反事实控制：保持G7为当前基线，构建同一来源同时具有正负标签的
训练/开发条件，并考虑带DADS回放约束的适配；不得继续在Kielce正类/TAU负类完全
绑定的数据上单独调整分类头。
