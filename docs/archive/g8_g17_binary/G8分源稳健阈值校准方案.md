# G8：分源稳健阈值校准方案

## 1. 结论与边界

G7已经证明AudioSet预训练带来真实的排序增益：相对同结构Scratch，`val_ood`
holdout ROC AUC提高0.04741，标准化`pAUC@FPR≤0.05`提高0.04138。但G7-PT依据
tune pooled负类分位数冻结的阈值迁移到holdout后，1%和5%工作点实际FPR分别为
3.7685%和9.0175%，超过2%和7.5%的开发门槛。

G8不改模型、不重新训练、不重新拟合温度，只研究一个问题：把统计单位从高度相关的
音频片段改为原始背景来源块，能否在保留足够TPR的同时改善阈值跨来源迁移。

G8仍属于`val_ood`开发分析。该holdout已经在G7中被查看，不能将G8称为无偏最终
确认；Unseen和Real-world继续锁定，G8失败时不得通过读取锁定集调阈值。

## 2. 冻结算法

实现版本固定为`g8_source_block_order_statistic_v1`。对每个目标FPR
`α ∈ {0.01, 0.05}`，只使用`val_ood tune`中标签为0的样本。

对背景来源`g`，样本数为`n_g`，分数按降序排列：

```text
s(g,1) >= ... >= s(g,n_g)
k_g = floor(α * n_g)
q_g = nextafter(s(g,k_g+1), +inf)
```

因此以`probability >= threshold`判为正类时，每个来源的经验误报数都不超过`k_g`。
并列分数必须通过`nextafter`向正无穷移动，不能直接使用普通分位数。

令来源误覆盖率`δ=0.05`，背景来源数为`G`：

```text
r = ceil((G + 1) * (1 - δ))
threshold = q_g升序排列后的第r个值
```

当前tune包含25个背景来源，`r=25`，对应来源块覆盖下界`25/26=96.15%`，所以
最终阈值是25个来源局部阈值的最大值。若来源数不足以使`r <= G`，程序直接失败，
不能回退到pooled阈值。

这只是在“未来来源块与tune来源块可交换”假设下的经验来源覆盖，不是跨数据集总体FPR
证明。每个来源只有26–38个片段，尤其不能声称已经统计证明单来源真实FPR小于1%。

## 3. 两阶段物理隔离

### 3.1 Fit阶段

Fit入口只接受tune predictions和权威tune manifest，不存在holdout参数。它完成：

- 在读取前拒绝路径名、解析后的软链接目标或CSV行内的Unseen/Real-world标识；
- 强制`dataset=val_ood`、`ood_split=tune`；
- 严格验证二元整数标签、64位SHA256、无重复样本；
- 逐列绑定prediction与权威manifest身份；
- 只用负类和`background_source`生成阈值；
- 原子写入冻结阈值JSON，已有文件时拒绝覆盖。

冻结产物：

```text
artifacts/g8_source_robust/frozen_thresholds/g7_panns_pt_seed42.json
```

### 3.2 Evaluate阶段

Evaluate入口读取冻结JSON后才应用到holdout，并再次核对：

- tune prediction和manifest SHA256与冻结记录完全一致；
- reference metrics绑定相同的tune/holdout prediction SHA256；
- tune与holdout的样本SHA256、背景来源、UAV来源均零重叠；
- ROC AUC、PR AUC和partial AUC与G7-PT逐项一致；
- 阈值只被应用，不重新计算。

输出目录：

```text
artifacts/g8_source_robust/evaluation/g7_panns_pt_seed42/
├── metrics.json
└── operating_points.csv
```

## 4. 失败关闭门控

两个工作点必须同时满足全部条件：

| 条件 | 1%工作点 | 5%工作点 |
|---|---:|---:|
| holdout实际FPR上限 | 0.020 | 0.075 |
| holdout TPR下限 | 0.10 | 0.30 |
| 相对原G7-PT TPR保留率 | ≥0.80 | ≥0.80 |
| FPR相对原G7-PT | 不得增加 | 不得增加 |
| 背景来源macro FPR | 不高于G2对应值+0.02 | 不高于G2对应值+0.02 |

设置TPR绝对下限和80%保留率，是为了防止仅靠极高阈值制造“低误报改善”。任一条件
失败，决策写为`do_not_promote`，不运行seed 43/44，也不解锁最终外部集。
