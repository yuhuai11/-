# G13 新外部确认集接入与一次性评估方案

## 1. 当前结论

现有服务器目录中没有能够直接作为 G13 无偏确认集的数据。DADS、`val_ood`、ESC-50 困难负类、Unseen 和 Real-world 均已参与训练、开发或最终分析；同源数据的重新切片、增强或改名不能被视为新外部测试。

G13 因此分为三个阶段：新数据接入审计、读取前协议冻结、一次性 GPU 评估。当前代码只实现第一阶段，不会自动读取模型预测或运行最终评估。

## 2. 新数据最低要求

- 正负类各不少于 1,000 个独立 1 秒 WAV；
- 每类不少于 10 个来源组；
- 每个来源组不少于 50 个样本；
- 音频时长为 0.95～1.05 秒；
- 所有音频 SHA256 唯一；
- 与 DADS、`val_ood`、G9 困难负类及旧外部测试的音频 SHA256 交集为零；
- 每个来源必须登记采集批次、来源说明、授权状态，并声明独立于已有数据。

每类 1,000 个样本只能提供约 0.1% 的经验 FPR 分辨率；如果后续需要更精确地证明 1% 以下 FPR，应继续增加负样本和独立背景来源。

## 3. 目录结构

```text
data/external_confirmation_v2/
├── source_registry.csv
├── Background/
│   ├── background_site_01/
│   │   ├── clip_0001.wav
│   │   └── ...
│   └── background_site_10/
└── UAV/
    ├── uav_site_01/
    │   ├── clip_0001.wav
    │   └── ...
    └── uav_site_10/
```

允许在来源目录下增加一层条件目录，例如 `traffic/`、`wind/` 或 `distance_50m/`。来源登记模板位于 `data_templates/g13_source_registry_template.csv`。

## 4. 接入审计

数据准备完成后运行：

```bash
cd /home/user1/JJZ/ABDDV-CRNN
mkdir -p logs

bash scripts/run_g13_intake_audit.sh \
  2>&1 | tee logs/g13_intake_audit.log
```

审计只生成不可变 manifest、读取音频元数据和 SHA256，并与历史 manifest/DADS 原始音频做交叉去重。读取旧 Unseen/Real-world manifest 时只读取哈希列，不读取预测或指标，并在审计文件中明确记录。

## 5. 冻结后的候选系统

- 正式基线：G7；
- 候选严格模式：G9 三种子 raw-logit 集成，温度沿用 G10，阈值固定为 G12 的 `0.7088954330786355`；
- 平衡模式：继续使用 G7，不作为 G13 候选；
- 新确认集不得用于阈值搜索、温度拟合、样本筛选或模型修改。

## 6. 一次性晋级门槛

G13 在新数据接入审计通过后才生成和冻结最终执行器。严格模式必须同时满足：

1. 候选 FPR 不高于 G7；
2. 候选 TPR 不低于 G7；
3. 候选 F1 不低于 G7；
4. 背景来源宏平均 FPR 不高于 G7；
5. UAV 来源宏平均 TPR 不低于 G7；
6. 低 FPR Partial-AUC 不低于 G7。

如果任何门槛失败，保持 G7，不允许在同一确认集上修改阈值后重试。
