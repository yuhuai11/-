# G7 模型结果与性能分析报告

## 1. 报告目的

本文档汇总“声学无人机检测与开放集型号识别系统”中G7正式基线的模型结构、训练数据、数据划分、
音频预处理、训练算法、历史DADS同源内部回归结果、外部泛化结果及其相对原始工程的改进。

当前正式模型仍为：

```text
G7 PANNs Cnn14_16k AudioSet 预训练模型（seed 42）
```

正式检查点：

```text
artifacts_g7_panns_pt/runs/seed_42/best.pt
```

检查点 SHA256：

```text
d357f194105ec27a61838e0f4c2e7575932e2dd861e529ef970b1fb467954cdc
```

G14、G15、G16 均为 G7 之后的开发实验。其中 G16 虽然改善了部分多 SNR
指标，但没有通过低 SNR TPR 安全门，因此没有替代 G7。

---

## 2. 总体结论

G7 在历史DADS同数据源已消费内部回归集上已经接近饱和：

- 历史DADS已消费内部回归F1：`0.996992`；
- 历史DADS已消费内部回归Recall：`0.998567`；
- 历史DADS已消费内部回归Specificity：`0.993305`；
- 历史DADS已消费内部回归ROC-AUC：`0.999854`；
- 历史DADS已消费内部回归PR-AUC：`0.999913`。

45,891 个历史DADS回归片段中只有164个错误，因此继续围绕该同源内部回归F1
进行优化，最大理论提升也只有约 `0.003`。后续模型在内部指标上通常只能取得千分位
变化，并且可能以牺牲外部召回或增加困难背景误报为代价。

但是 G7 在全新真实外部域上尚未饱和。G13 一次性外部确认中：

- F1：`0.6165`；
- Recall：`55.0854%`；
- Specificity：`97.4361%`；
- FPR：`2.5639%`；
- ROC-AUC：`0.9175`；
- PR-AUC：`0.6836`；
- 最差 UAV 来源 TPR：`11.7241%`；
- 最差背景来源 Specificity：`57.7320%`。

因此，G7 的正确定位是：

> 历史DADS同源内部回归集上的高性能正式基线；相比原始CRNN和ResNet10-CBAM
> 显著改善了外部 F1、召回和低误报工作能力，但跨设备、跨来源及低 SNR 泛化仍有
> 明显提升空间。

## 3. 训练数据与数据划分

### 3.1 数据来源

G7 本体训练只使用 DADS 数据。原始音频位于：

```text
date/DADS/data/
```

数据存储在 39 个 Parquet 文件中，Parquet 行内保存 WAV 音频字节及其标签。

G7 使用的历史清单为：

```text
artifacts_full/manifests/dads_all_seed42.csv
```

配置采用全部 DADS 数据：

```yaml
per_class: all
manifest_seed: 42
splits:
  train: 0.70
  val: 0.15
  test: 0.15
```

G7 没有使用 `5000/类` 或 `15000/类` 的子集。

### 3.2 历史清单实际规模

| 划分 | 背景片段 | UAV片段 | 总片段 | Parquet行/AudioRef数 |
|---|---:|---:|---:|---:|
| Train | 87,974 | 124,528 | 212,502 | 126,224 |
| Validation | 18,670 | 27,943 | 46,613 | 27,048 |
| 原Test（已消费内部回归） | 18,670 | 27,221 | 45,891 | 27,048 |
| 总计 | 125,314 | 179,692 | 305,006 | 180,320 |

每个训练片段长度为 1 秒，即 16 kHz 下的 16,000 个采样点。

历史`prepare_manifest`实际在每个标签内随机把Parquet行（`AudioRef`）分配到
Train、Validation和Test，再展开每行的1秒片段；因此同一Parquet行产生的片段不跨
split。它没有把`source_path`作为分组键。历史清单的路径交集事后检查满足：

```text
train ∩ validation 的 source_path = 0
train ∩ 原test       的 source_path = 0
validation ∩ 原test  的 source_path = 0
```

这只是路径字符串的事后身份审计结果，不是划分方法，也不能证明物理录音内容、会话、
设备、场景或型号隔离。

### 3.3 后续原始音频哈希去重审计

G7完成后，G14阶段对Parquet中原始WAV字节计算SHA256，发现：

- 15个重复SHA256组；
- 这些组共涉及30条Parquet记录；
- 每组保留1条代表，共移除15条冗余记录；
- 其中6组的成员原本跨至少两个split；
- 移除15条冗余记录连带移除244条由历史流程生成的1秒manifest片段。

去重后的 DADS dedup v2：

| 划分 | 去重后片段 |
|---|---:|
| Train | 212,338 |
| Validation | 46,565 |
| 原Test（已消费内部回归） | 45,859 |
| 总计 | 304,762 |

旧dedup v2处理后，train、validation、原test的原始音频SHA256、`recording_group`
和`source_path`交集均为0。这是移除重复记录后的结果，不是全局重新分组或重新划分；
代表记录仍保留其`original_split`。

需要说明：G7没有在dedup v2上重新训练，而且dedup v2也不是完整的无泄漏协议。它只
去除原始WAV字节级精确重复，仍复用旧1秒`loop/tail_loop`预处理和缓存，未消除标签
相关的时长/重复捷径。raw去重后，负类16,715条原始记录中仅2条恰为8000采样点
（0.0120%），而正类163,590条中有162,000条恰为8000采样点（99.0281%）。单用
`original_samples == 8000`作诊断，在历史已消费内部回归集上即可得到Accuracy
0.936480、Precision 1.000000、Recall 0.892914和F1 0.943428。这说明244条被移除
片段占比虽仅约`0.08%`，但不能据此认为旧流程的主要捷径已经解决。

原Test又被G2～G16等多轮候选门禁消费，因此本文将其限定为“历史DADS同数据源已消费
内部回归集”。新的论文级主复现应使用
`dads_native_half_second_content_component_v2`：从原始WAV构造16 kHz、8000采样点
的原生0.5秒窗口，不循环、不补齐、不拉伸，并让原始与最终模型输入内容组件整体划分；
旧dedup v2只用于历史对照。

去重审计：

```text

```

## 5. 音频预处理

G7 的输入处理流程为：

```text
WAV字节
  → PCM解码
  → 多声道平均为单声道
  → 多相重采样至16 kHz
  → 裁剪或循环补齐至1秒
  → 峰值归一化
  → 训练阶段波形增强
  → PANNs内部STFT与Log-Mel
  → Cnn14
  → 二分类Logit
  → Sigmoid概率
```

这是现有正式G7检查点的**历史1秒流程**，用于解释既有结果，不是下一轮推荐的数据
协议。其“短音频循环补齐至1秒”会保留上述标签相关时长/重复捷径；新主复现必须从
原始WAV重新构造原生0.5秒内容组件隔离数据，不能复用该1秒缓存。

### 5.1 WAV解码

支持：

- 8-bit PCM；
- 16-bit PCM；
- 24-bit PCM；
- 32-bit PCM。

多声道音频通过通道平均转换为单声道，输出为 `float32`。

### 5.2 重采样

使用 `scipy.signal.resample_poly` 将所有音频统一为 16 kHz。

### 5.3 固定长度

- 长于 1 秒：训练时随机裁剪，验证/测试时确定性裁剪；
- 短于 1 秒：循环复制至 16,000 点；
- 空音频：补零。

### 5.4 归一化

每条音频除以自身绝对峰值。该处理可以减小不同录音增益的影响，但会弱化绝对响度和
距离信息。

### 5.5 缓存

预处理片段位于：

```text
artifacts_full/audio_cache/
```

训练时优先通过 Numpy 文件或内存映射读取，减少 Parquet 解码开销。

## 7. 模型结构

### 7.1 模型名称

```text
PANNs Cnn14_16k
```

G7 不是原始 CRNN，也不是 ResNet10-CBAM。

### 7.2 预训练

使用官方 AudioSet 527 类监督预训练检查点：

```text
artifacts/g7_panns/checkpoints/Cnn14_16k_mAP=0.438.pth
```

官方预训练 SHA256：

```text
e2ee543a27919542c2ea03eabaa70b24dcd4e6c8e05621de6b67a94e4c5058e6
```

G7 首先加载完整 AudioSet 权重，然后将原 527 类输出层替换为一个
`2048 → 1` 的二分类线性层。

### 7.3 PANNs声谱前端

| 参数 | 设置 |
|---|---:|
| Sample rate | 16,000 Hz |
| STFT window | 512采样点，约32 ms |
| Hop size | 160采样点，10 ms |
| Mel bins | 64 |
| 最低频率 | 50 Hz |
| 最高频率 | 8,000 Hz |

### 7.4 网络主干

```text
Log-Mel
  → BatchNorm
  → Conv Block 1
  → Conv Block 2
  → Conv Block 3
  → Conv Block 4
  → Conv Block 5
  → Conv Block 6
  → 时间维Max Pool + Mean Pool
  → FC 2048
  → 二分类Linear Head
```

全局池化同时使用时间最大值和时间平均值，兼顾局部显著声学证据与整段平均特征。

### 7.5 参数量与训练范围

```text
总参数：79,955,457
训练范围：完整模型微调
```

G7 是完整网络微调。后来的 G14、G15、G16 才主要采用只训练二分类头的方案。

### 7.6 SpecAugment

```yaml
spec_augment: false
```

G7 没有启用 PANNs 内置时频遮挡，主要增强发生在原始波形层。

## 8. 训练算法

### 8.1 损失函数

使用：

```text
BCEWithLogitsLoss
```

自动正类权重：

```text
pos_weight = 训练背景数 / 训练UAV数
           = 87,974 / 124,528
           ≈ 0.7065
```

### 8.2 优化器与学习率

```text
优化器：Adam
初始学习率：1e-4
每轮指数衰减系数：0.75
```

### 8.3 Batch与epoch

```text
Batch size：128
每轮约1,661步
最大epoch：15
```

每轮随机打乱并自然遍历完整训练集，不采用有放回过采样。

### 8.4 早停与模型选择

```text
早停耐心：4轮
模型选择指标：Validation F1@threshold 0.5
```

实际结果：

- 最佳 epoch：7；
- 最佳 Validation F1：`0.996909`；
- epoch 11 后早停；
- 总训练时间约 47.9 分钟。

### 8.5 混合精度

CNN 使用 AMP 混合精度。STFT、Log-Mel 和 `bn0` 强制使用 FP32，以避免真实强谱峰
在 FP16 频谱平方中溢出。

### 8.6 随机性

正式 G7 只使用：

```text
seed = 42
```

固定 Python、NumPy、PyTorch、CUDA、DataLoader 及 cuDNN 确定性状态。
单随机种子是当前 G7 证据的一个限制，后续严格复现应补充 seed 43 和 44。

## 10. 指标含义

### 10.1 Accuracy

```text
(TP + TN) / 全部样本
```

表示总体正确率，但在类别不平衡时可能被多数类主导。

### 10.2 Balanced Accuracy

```text
(Recall + Specificity) / 2
```

同时衡量 UAV 检出和背景排除，比 Accuracy 更适合当前任务。

### 10.3 Precision

```text
TP / (TP + FP)
```

表示报警为 UAV 时，该报警真正正确的概率。

### 10.4 Recall/TPR/Sensitivity

```text
TP / (TP + FN)
```

表示真实 UAV 中被成功检出的比例。

### 10.5 Specificity

```text
TN / (TN + FP)
```

表示真实背景中被正确排除的比例。

### 10.6 FPR

```text
FP / (FP + TN) = 1 - Specificity
```

表示背景被误报为 UAV 的比例。连续部署时应进一步换算为每小时误报次数。

### 10.7 F1

```text
2 × Precision × Recall / (Precision + Recall)
```

用于平衡误报和漏检，但 F1 不包含 TN，不能替代 Specificity 和 FPR。

### 10.8 ROC-AUC

衡量所有阈值范围内的正负样本排序能力。完整 ROC-AUC 可能被大量容易背景样本主导，
因此部署场景还应关注低 FPR 区域。

### 10.9 PR-AUC

综合不同阈值下 Precision 与 Recall，类别不平衡时通常比 ROC-AUC 更具解释力。

### 10.10 低FPR partial AUC

只计算 `FPR ≤ 0.05` 的 ROC 区域，更符合无人机低误报监测要求。

### 10.11 内外部评价指标统一对齐

为了避免把“数据域差异”和“评价口径差异”混在一起，历史DADS已消费内部回归集与外部数据统一采用
以下协议：

| 对齐项目 | 统一设置 |
|---|---|
| 任务 | 二分类，UAV=`1`，背景=`0` |
| 评价单位 | 1秒片段级；不使用文件级 Mean/Max 聚合 |
| 模型 | 同一 G7 seed 42 检查点 |
| 概率 | G7 Logit 经同一温度 `T=2.2583125279` 校准 |
| 严格低误报阈值 | `0.7236399840`，仅由 val_ood Tune 背景确定 |
| 平衡阈值 | `0.5085329109`，仅由 val_ood Tune 确定 |
| 阈值相关指标 | Accuracy、Balanced Accuracy、Precision、Recall、Specificity、FPR、F1、TP/FP/TN/FN |
| 阈值无关指标 | ROC-AUC、PR-AUC、标准化 pAUC（FPR≤0.05） |

其中 DADS 保存的是未校准 Sigmoid 概率。对齐时先还原 Logit，再使用与外部评估相同
的温度缩放；val_ood、Unseen、Real-world 和 G13 使用各自冻结预测文件中已经校准的
`G7 probability`。温度缩放是单调变换，不改变 ROC-AUC、PR-AUC 和 pAUC。

#### 对齐后的解释

- 历史DADS已消费内部回归集、Unseen和Real-world的Accuracy可参考，因为正负类接近平衡；
- G13 背景占 `90.2%`，Accuracy 会受到多数类主导，应优先看 Balanced Accuracy、
  Recall、Specificity、FPR、F1、PR-AUC 和来源级最差性能；
- 严格模式与平衡模式使用完全相同的模型，只改变决策阈值；
- 严格模式在 Unseen 上把 FPR 压至 `0.187%`，但 Recall 只有 `15.964%`；
- 平衡模式提高各外部数据的 Recall，但 G13 FPR 上升到 `10.064%`，说明该阈值不适合
  直接作为 G13 的低误报部署阈值；
- Real-world 结果很高，但只有 546 个平衡样本，不能抵消 val_ood、Unseen 和 G13
  揭示的跨来源泛化问题；
- G13 平衡阈值结果是基于已经冻结的预测做的补充性统一统计，不改变 G13 原预注册的
  严格模式结论，也不能用于重新选择模型或阈值。

因此，后续所有候选模型都应按以上两套冻结阈值和三类阈值无关指标同时报告，不能只
比较某一个数据集的 F1，也不能分别为每个测试集寻找最优阈值。

## 15. 现有证据说明了什么

### 15.1 已经较强的方面

- 历史DADS同源内部回归区分能力接近饱和；
- Real-world 上的 F1 和 Recall 相比原始模型大幅提高；
- AudioSet 预训练明显改善了低误报区域的外部检测能力；

  该结论不反推历史DADS具备会话、设备、场景或型号隔离。

### 15.2 尚未解决的方面

- G13 仍漏检约 45% UAV；
- 最差 UAV 来源 TPR 只有 11.72%；
- 最差背景来源 Specificity 只有 57.73%；
- `-15/-10 dB` 低 SNR 正类召回不足；
- 外部来源之间差异很大；
- G7尚未完成原生0.5秒内容组件隔离协议下的多随机种子复现；旧dedup v2仍含1秒
  时长/重复捷径；
- 峰值归一化可能丢失与距离相关的绝对响度信息；
- 训练增强中的最低 SNR 仅为 `-5 dB`。

## 18. 后续研究方向

后续不应继续把主要目标设为提高 DADS F1，而应转向：

```text
提高跨来源TPR
提高低SNR Recall
提高固定FPR下的检出率
改善最差来源
改善概率校准
同时保持DADS非劣
```

建议执行顺序：

1. 基于现有预测完成阈值扫描与配对置信区间诊断；
2. 在`dads_native_half_second_content_component_v2`原生0.5秒内容组件隔离协议上
   复现G7；
3. 补充 G7 seed 43、44；
4. 增加低 SNR 正样本绝对概率损失，而不是只优化正负排序；
5. 若 head-only 容量不足，受控解冻 PANNs 最后高层特征块；
6. 增加不同机型、距离、设备和真实背景下的独立 UAV 录音；
7. 预先冻结新候选和晋级门槛；
8. 使用新的、从未参与开发的来源隔离确认集进行一次性最终评估。
