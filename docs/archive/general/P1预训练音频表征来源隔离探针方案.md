# P1：预训练音频表征来源隔离探针方案

## 1. 方向切换依据

G2通过训练期声学增强把val_ood holdout F1从0.62084提高到0.70955，是当前唯一获得大幅、整体外部收益的方案。G3来源均衡、G4低SNR重分配、G5 MFCC-64和G6时序注意力均未替代G2；现有Full ResNet10-CBAM三个seed的val_ood F1也只有约0.58至0.60。继续从头训练小型结构的证据收益已经不足。

2026-07-18完成的域差距审计进一步显示：

- val_ood tune/holdout的UAV来源分别为14/16个，重叠0个；
- 背景来源分别为25/34个，重叠0个；
- G2 holdout共有206个漏检、223个误报，错误Top-3来源分别只占30.6%和29.6%，不是单一异常文件造成；
- 最差UAV来源`DRONE_015.wav` Recall仅0.34211；
- `BACKGROUND_012.wav`、`BACKGROUND_005.wav`等背景录音几乎整段被误报；
- G2有40条距离冻结阈值至少0.10仍判错的样本，说明单纯重新校准不能解决全部错误。

因此下一步不再做CRNN池化、MFCC或小幅增强概率变体，而检验“大规模通用音频预训练表征是否能缓解来源迁移”。

## 2. 唯一候选与实验性质

首个候选固定为Microsoft官方BEATs Iter3+ AS2M预训练编码器。官方实现提供16 kHz波形输入和`extract_features`接口，与本工程现有16 kHz音频处理口径兼容：

- 官方代码与权重说明：https://github.com/microsoft/unilm/tree/master/beats
- 论文与方法说明：https://www.microsoft.com/en-us/research/publication/beats-audio-pre-training-with-acoustic-tokenizers/

P1只是冻结表征探针，不是直接候选冠军：

1. BEATs全部参数冻结，不进行微调；
2. 对时间帧表征执行带padding mask的均值池化；
3. 只训练一个L2正则的线性二分类头；
4. 不加入G2/G6 logits、不做模型集成、不改变外部阈值规则；
5. 只有探针证明来源迁移收益后，才单独设计微调或蒸馏方案。

PANNs/AST只作为BEATs无法运行时的预注册备选，不与BEATs同时搜索并择优报告。

## 3. 数据边界

### 3.1 DADS训练与内部验证

快速探针使用现有：

`archive/historical_models/baselines/artifacts_15000/manifests/dads_balanced_15000_seed42.csv`

该清单沿用历史流程：先在每个标签内随机把Parquet行（`AudioRef`）分配到train、
val和test，再把每行展开成1秒片段，因此同一行的片段不跨split；`source_path`不是
实际分组键，三个split的路径交集为0只是事后身份审计结果。全量DADS后验原始WAV
字节级SHA256审计共发现15个重复哈希组，涉及30条Parquet记录；每组保留1条并移除
15条，其中6组成员原本跨至少两个split，连带移除244条历史1秒manifest片段。P1使用
的balanced-15000清单也命中了这6组跨split精确内容重复，因而路径零交集不等于物理
来源或内容隔离。

DADS又没有足够的会话、设备、场景和无人机型号元数据来证明这些层面的隔离。该集合
也已参与多轮候选门禁，因此下文统一称为“历史DADS同数据源已消费内部回归集”。旧
`dads_dedup_v2`只修复原始WAV字节级精确重复，仍复用历史1秒`loop/tail_loop`
预处理和缓存，未消除标签相关的时长/重复捷径。因此P1的近满分内部指标只作历史诊断；
若重做预训练表征探针，应使用`dads_native_half_second_content_component_v2`
原生0.5秒内容组件隔离协议。为避免长录音产生的多个segment支配线性头：

- 每个`source_path`最多确定性选择3个segment；
- 少于3个时全部保留；
- 选择顺序固定为首段、中段、末段；
- 训练损失按`source_path`等权，不进行G3式有放回来源均衡；
- 推理时先得到segment概率，再按`source_path`取均值产生内部路径聚合指标。

### 3.2 val_ood开发验证

只允许：

- tune：拟合temperature和冻结阈值；
- holdout：一次性开发评估和来源级对比。

当前holdout已经用于多轮方案选择，因此P1结果只能称开发证据。Unseen和Real-world继续锁定，脚本必须明确拒绝包含这两个名称的输入路径。

## 4. 快速筛选门槛

P1的目标是判断预训练表征是否值得继续，不要求冻结线性头立即达到G2的DADS 99.5%：

| 项目 | 快速探针要求 |
|---|---:|
| 历史 DADS 同数据源已消费内部回归集AUC（`source_path`聚合） | ≥0.98 |
| 历史 DADS 同数据源已消费内部回归集F1（`source_path`聚合） | ≥0.95 |
| val_ood holdout AUC | ≥G2 + 0.03，即≥0.79072 |
| val_ood holdout F1 | ≥G2 − 0.01，即≥0.69955 |
| val_ood来源macro Recall | 不低于G2 − 0.02 |
| val_ood来源macro Specificity | 不低于G2 − 0.02 |

若AUC没有至少3个百分点的提升，说明通用预训练表征没有形成足够信号，停止P1，不进行微调。若AUC明显提升但工作点不稳定，则下一步研究来源稳健校准；若AUC、F1和来源宏平均同时通过，才设计BEATs轻量微调或蒸馏到小模型。

## 7. 实际结果与门控结论

2026-07-18已完成全量P1。末尾出现的
`RuntimeError: P1 frozen BEATs probe did not pass its continuation gate`
是门控按设计拒绝候选，不是训练或推理故障。完整机器可读结果位于
`artifacts/p1_beats_probe/evaluation/gate.json`。

| 指标 | P1结果 | 门槛 | 结论 |
|---|---:|---:|---|
| 历史 DADS 同数据源已消费内部回归集AUC（`source_path`聚合） | 0.9999998 | ≥0.98 | 通过 |
| 历史 DADS 同数据源已消费内部回归集F1（`source_path`聚合） | 0.9995556 | ≥0.95 | 通过 |
| val_ood holdout AUC | 0.7324988 | ≥0.7907220 | 失败 |
| val_ood holdout F1 | 0.6358382 | ≥0.6995464 | 失败 |
| UAV来源macro Recall | 0.6100999 | ≥0.6905648 | 失败 |
| 背景来源macro Specificity | 0.6905552 | ≥0.6837012 | 通过 |

P1在历史 DADS 同数据源已消费内部回归集的`source_path`聚合口径上近乎满分，但这不是
跨会话、跨设备、跨场景或跨型号的独立泛化结果。外部来源迁移仍显著退化：相比G2，
holdout AUC下降0.02822，F1下降0.07371，UAV来源macro Recall下降0.10046；只有背景
来源macro Specificity接近G2并满足非劣门槛。tune上的Recall≥0.80、
Specificity≥0.90联合约束同样不可行。因此冻结BEATs表征没有证明可直接替代G2，也
没有达到进入BEATs微调阶段的预注册条件，正式决策为`stop_p1`。

## 8. 互补性诊断与下一步边界

P1单模型失败不等于其信息与G2完全重复。逐样本配对显示：

- tune：G2独有正确210条，BEATs独有正确362条，两者都错180条；
- holdout：G2独有正确344条，BEATs独有正确269条，两者都错160条；
- holdout两模型校准概率的Pearson相关系数仅0.3542。

这说明BEATs包含可供融合研究的互补信号。作为只读探索，按tune AUC选择的概率
加权为`0.40×G2 + 0.60×BEATs`，再只用tune冻结阈值；其holdout AUC为0.78078，
但F1仅0.68530，仍低于G2。事后观察到更偏向G2的权重可能更好，不能据此选择，
否则构成对holdout的再次拟合。

下一候选应单独预注册为P2融合验证：冻结G2与P1模型，不做BEATs微调；只在来源
隔离的开发折上学习融合器，并通过来源级交叉验证或新建未使用开发折选择权重。
现有holdout只用于报告，不再承担P2权重选择。P2只有同时保持历史 DADS 内部回归指标、提高
外部AUC和F1且不降低UAV/背景来源宏平均时才可替代G2；否则停止模型侧搜索，转向
补充目标域训练来源和困难负类数据。Unseen与Real-world继续锁定。
