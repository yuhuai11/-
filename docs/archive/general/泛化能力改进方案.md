# 声学无人机检测与开放集型号识别系统：泛化能力改进方案

## 1. 当前结论

当前15个模型已在Unseen与Real-world数据上完成冻结评估。历史DADS同数据源已消费
内部回归集F1接近99%，但外部模型普遍表现为高Specificity、低Recall：Full CRNN在
Unseen的Recall为16.21%，Full ResNet10-CBAM为10.52%；Real-world分别为45.79%和
54.46%。

因此下一阶段的首要目标是减少跨域无人机漏检，而不是继续提高历史DADS同数据源内部
回归指标。Unseen和Real-world已经查看过结果，从此只能作为已消费且关闭的历史外部
对照，不能继续用于模型选择、阈值选择或增强参数选择。

历史DADS清单实际是在每个标签内随机把Parquet行（`AudioRef`）分配到Train、
Validation和Test，再把每行展开成1秒片段；同一行的片段不跨split，但
`source_path`不是实际分组键，其零交集只是事后身份审计结果。后验原始WAV字节级
SHA256审计发现15个重复哈希组，共涉及30条Parquet记录；每组保留1条并移除15条，
其中6组成员原本跨至少两个split，连带移除244条历史1秒manifest片段。原Test已被
多轮候选门禁消费。

旧`dads_dedup_v2`仅去除原始WAV字节级精确重复，仍复用历史1秒
`loop/tail_loop`预处理和缓存，未消除标签相关时长/重复捷径。后续主重训应采用
`dads_native_half_second_content_component_v2`原生0.5秒内容组件隔离协议。本文
保留历史数值用于同数据源已消费内部回归比较，但不把它作为独立泛化证据。

## 2. 总体路线

```text
外部来源分组的已消费val_ood开发集
→ 阈值与温度校准基线
→ 正类声学增强
→ 来源均衡与新来源覆盖
→ 特征/结构受控消融
→ 三随机种子冻结确认
```

## 3. 第一阶段：val_ood外部来源分组开发集

### 3.1 数据构成

第一阶段使用服务器现有但未被当前ABDDV模型训练的候选数据作为只读来源：

```text
/home/user1/JJZ/Acoustic-UAV-Identification/
  data/dataset_generalization_g1/val_ood
```

数据共3,000条、正负类各1,500条，采样率44.1 kHz、每条1秒：

- 正类来自GitHub U17的30个无人机录音组；
- 正类包括256条UAV-only及1,244条UAV+Background；
- 混合条件覆盖 `-15/-10/-5/0/+5/+10 dB`；
- 负类覆盖59个背景来源；
- 当前工程重新生成SHA256并独立审计，不直接信任来源工程的旧结论。

### 3.2 两级验证划分

按照完整 `source_group` 拆分，禁止同一无人机录音组或背景来源跨子集：

- `tune`：用于拟合temperature和选择阈值；
- `holdout`：用于确认校准及候选模型，不参与校准拟合。

拆分目标为每类约50%，固定seed `20260716`。所有拆分信息写入manifest，保证可重复。

### 3.3 审计门槛

只有同时满足以下条件才允许进入第二阶段：

1. 正负类均为1,500条；
2. 标签之间无相同SHA256；
3. 与DADS原始WAV无精确重叠；
4. 与Unseen、Real-world无精确重叠；
5. tune和holdout来源组交集为0；
6. 元数据不包含最终测试源关键词；
7. 最终测试manifest必须存在，不能跳过交叉审计。

精确哈希不能发现重编码近重复，因此第一阶段通过只代表精确重复和已知来源检查通过。后续仍应补充音频指纹审计。

## 4. 第二阶段：不重新训练的校准基线

先对Full CRNN和Full ResNet10-CBAM执行：

1. 在`tune`拟合temperature scaling；
2. 在`tune`选择满足Recall约束的阈值；
3. 在`holdout`冻结验证；
4. 输出ECE、可靠性图、Recall、Specificity、F1和AUC。

建议门槛：

```text
holdout Recall ≥ 80%
holdout Specificity ≥ 90%
```

如果AUC较高但固定阈值Recall低，而校准后holdout明显改善，说明概率尺度偏移占重要部分；否则进入训练数据改造。

### 4.1 第二阶段实际结论

Full CRNN与Full ResNet10-CBAM的seed 42/43/44已经完成tune-only温度和阈值拟合，以及holdout冻结验证。6个检查点均无法在tune同时满足Recall不低于80%和Specificity不低于90%。

温度缩放显著降低ECE和NLL，但固定阈值0.50的分类结果不变；诊断阈值虽然把holdout Recall提高到约52%～58%，却把Specificity降至约66%～75%。因此当前失效不只是概率校准问题，第二阶段判定为“校准改善概率可信度，但无法解决分类泛化”，下一步正式进入训练数据改造。

完整结果见 `artifacts/val_ood/OOD校准评估报告.md`。

第二阶段批量运行命令：

```bash
PYTHONPATH=src python -m dads_crnn.run_ood_calibration \
  --config configs/val_ood.yaml
```

汇总命令：

```bash
PYTHONPATH=src python -m dads_crnn.summarize_ood_calibration
```

输出到 `artifacts/val_ood/calibration/`、`predictions/`、`metrics/`、`figures/` 和
`OOD校准评估报告.md`。

## 5. 第三阶段：数据增强Full基线

保持Full CRNN结构不变，先只改变训练数据：

- 使用训练负类与训练正类混合；
- SNR采用 `-5/0/+5/+10 dB`，不让极低SNR主导；
- 加入轻微混响、麦克风频响、带通/EQ、粉红噪声和非循环时间平移；
- 保留原始正类；
- 困难负类增加交通、发动机、风扇和稳态机械声，但不得使用最终测试文件。

当前峰值归一化与逐样本特征标准化会抵消单纯整体增益，因此优先使用能改变频谱和信噪结构的增强。

第三阶段已落地为[G2全量CRNN声学增强方案](../g2_g6_legacy/G2全量CRNN声学增强方案.md)，配置为
`configs/crnn_dads_full_augmented_g2.yaml`。首轮只运行seed 42。

Seed 42已完成。历史DADS同数据源已消费内部回归集F1为0.99522，相对原Full CRNN仅
下降0.31个百分点；val_ood holdout在tune冻结阈值下达到F1 0.70955、Recall
0.71781、Specificity 0.69987、AUC 0.76072。相对原Full CRNN，跨域F1、Recall和
AUC均明显提高，但双门槛仍不可行。因此G2判为“方向有效、未达部署门槛”，不扩展
seed 43/44，转入来源均衡和困难条件覆盖。

## 6. 第四阶段：来源均衡

训练采样采用：

```text
类别 → 来源/录音组 → 片段
```

新增metadata字段：`source_id`、`recording_id`、`augmentation`、`target_snr_db`和`achieved_snr_db`，避免长录音主导训练。

第四阶段已落地为[G3来源均衡采样方案](../g2_g6_legacy/G3来源均衡采样方案.md)。现有manifest的`source_path`直接作为`recording_id`，无需修改或复制音频；配置为`configs/crnn_dads_full_augmented_g3_source_balanced.yaml`，首轮只运行seed 42。

G3 seed 42已完成但未通过历史DADS已消费内部回归保护门槛：回归集F1为0.95316，相对原Full CRNN下降4.52个百分点，AUC降至0.98452。完全来源均衡导致正类覆盖不足并过度削弱长录音，因此停止该分支，不运行val_ood和其他种子。若重试采样策略，只允许保留自然类别比例并采用温和的来源权重。

## 6.1 G4：低信噪比轻量覆盖

精确复核后不再重试来源采样，转为[G4低信噪比轻量覆盖方案](../g2_g6_legacy/G4低信噪比轻量覆盖方案.md)。G4回到G2自然shuffle，只把5%的`+10 dB`混合条件概率移到`-10 dB`，约影响全部训练样本的2.05%；不加入`-15 dB`。G4采用独立输出和champion–challenger门控，只有历史DADS已消费内部回归非劣且val_ood严格Pareto不退化、同时获得实质改善时才允许替代G2，否则自动保留G2。

G4 seed 42已完成。历史DADS已消费内部回归保护通过，但val_ood holdout的F1/Recall/Specificity/AUC分别为0.68256/0.68630/0.68102/0.73920，全部低于G2；仅目标`-10 dB` Recall提高4.63个百分点。门控判定`keep_g2`，证明低SNR微量覆盖产生条件间权衡而非整体提升。G4停止，不运行其他种子和最终外部测试集。

## 6.2 G5：同容量MFCC-64特征消融

数据分布修改连续出现整体退化后，下一步转入[G5全秩MFCC特征消融方案](../g2_g6_legacy/G5全秩MFCC特征消融方案.md)。G5保持G2的自然采样、全部增强、STFT帧参数、CRNN结构和1,012,193参数不变，仅将64维Log-Mel变换为同维全秩MFCC；不采用会同时缩减模型容量的MFCC-40。G5使用独立SHA256库存、逐样本身份核对、内部非劣门控和条件级防退化门控，首轮只运行seed 42。

G5 seed 42已完成，训练后完整性审计全部通过。固定阈值0.50下，Val F1由G2的0.99500降至0.99148，历史DADS已消费内部回归F1由0.99522降至0.99213，分别下降0.352和0.309个百分点，均超过预注册的0.2个百分点上限；该回归集Recall、Specificity和AUC分别为0.99067、0.99068和0.99935。内部回归硬门控判定`keep_g2`，因此没有运行val_ood、其他随机种子或最终外部测试。

G5说明全秩MFCC并非对当前CRNN的无损工程替换：DCT虽保持信息维数，却改变了二维卷积的局部邻域先验。当前主线继续保留G2的Log-Mel前端；不通过放宽门槛、事后调阈值或查看外部结果来挽救该候选。

## 6.3 G6：零初始化时序注意力池化

下一候选转向[G6零初始化时序注意力池化方案](../g2_g6_legacy/G6零初始化时序注意力池化方案.md)。G6完整保留G2的数据、声学增强、Log-Mel、CNN、BiGRU和分类器，只将BiGRU后12个时间步的直接均值替换为无bias的单头softmax注意力。打分权重全零初始化，初始函数与mean pooling等价；模型只增加256个参数（1,012,193→1,012,449，约0.0253%），且构模不额外消耗随机数。

G6补充了此前门控未覆盖的风险：历史DADS回归集`segment_kind`保护、候选checkpoint/metrics/预测数组哈希绑定、val_ood来源级宏平均，以及同时对UAV来源与背景来源施加权重的配对multiway Bayesian bootstrap。seed 42只有通过严格内部回归非劣关才允许运行一次val_ood；即使通过，也只称开发集冠军，最终确认仍需全新的外部来源隔离数据。

G6最终未晋级：holdout AUC和Specificity分别提高0.01260和0.03903，但F1与Recall分别下降0.01833和0.04932，多个条件级Recall及配对Bootstrap非劣检验失败，机器判定`keep_g2`。

## 6.4 新主线：域差距审计与预训练音频表征探针

2026-07-18已完成G2/G6 val_ood域差距审计，产物位于`artifacts/domain_gap_audit/`。审计确认tune/holdout的UAV和背景录音来源均为零重叠；G2的206个漏检和223个误报广泛分布于多个来源，同时存在整段近乎全部误判的困难录音和40条高阈值边际错误。现阶段停止CRNN局部结构微调，转入[P1预训练音频表征来源隔离探针方案](P1预训练音频表征来源隔离探针方案.md)：先用冻结BEATs编码器与线性头验证通用音频预训练是否产生至少3个百分点的外部AUC收益，再决定是否值得微调或蒸馏。

P1已于2026-07-18完成并由预注册门控拒绝。冻结BEATs线性探针在历史DADS
balanced-15000同数据源已消费内部回归集上的`source_path`聚合F1为0.99956。该清单
同样先随机分配Parquet行/AudioRef再展开片段；路径零交集只是事后检查，且仍命中6组
跨split精确内容重复，也无法证明会话、设备、场景或型号隔离。它还使用旧1秒预处理，
因此该内部近满分结果不能排除标签相关的时长/重复捷径。val_ood holdout AUC/F1仅为0.73250/0.63584，UAV来源
macro Recall为0.61010，均未达到继续门槛，因此不进行BEATs微调，G2继续作为冠军。
配对诊断
同时发现BEATs与G2存在明显误差互补（holdout有269条仅BEATs判对，概率相关系数
0.3542），故下一步只允许开展预注册的P2冻结融合验证；不得依据已经查看的holdout
事后选择融合权重。若来源级开发验证不能稳定超过G2，则模型侧局部优化正式停止，
转向新增目标域UAV来源与直升机等困难负类的训练数据建设。

参考2026年预训练与增强泛化论文后，主线进一步转为
[G7预训练与低误报率泛化方案](../g7_evolution/G7预训练与低误报率泛化方案.md)。G7-0已完成固定
FPR重评估：G2在tune校准1% FPR后holdout TPR仅0.96%；校准5% FPR后holdout TPR
为20.68%，实际FPR漂移到7.13%；holdout的`FPR≤0.05`标准化partial AUC仅0.54029。
因此后续不再以F1工作点作为唯一优化目标。G7-1将严格比较同结构PANNs Cnn14_16k
随机初始化与AudioSet初始化完整微调，先隔离验证预训练收益；P2融合降为备选。

## 7. 第五阶段：特征和模型消融

当前CRNN使用Log-Mel、ResNet使用MFCC，模型与特征影响相互混杂。数据方案有效后依次比较：

| 实验 | 模型 | 特征 |
|---|---|---|
| A0 | CRNN | Log-Mel |
| A1 | CRNN | MFCC |
| A2 | ResNet10-CBAM | MFCC |
| A3 | ResNet10-CBAM | Log-Mel |
| A4 | CRNN | PCEN或多分辨率Log-Mel |

结构改动最后考虑attention pooling、mean+max pooling或轻量多分辨率分支，不同时叠加多个变化。

其中A1已由G5完成并被内部关拒绝；G6先独立检验最小参数增量的attention pooling，不与A4前端变化同时实施。
