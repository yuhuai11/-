# G6：零初始化时序注意力池化与安全晋级方案

## 1. 目的与实验假设

G3来源均衡、G4低信噪比重分配和G5全秩MFCC均未替代G2。现有证据说明：继续修改训练分布会产生条件间权衡，直接替换Log-Mel也会降低历史DADS内部回归F1。G6因此保留G2的数据、声学增强和Log-Mel，只检验一个结构问题：BiGRU输出的12个时间步直接取均值，是否稀释了局部无人机证据。

当前路径为：

```text
Log-Mel [B,1,64,101]
→ CNN [B,128,8,12]
→ BiGRU [B,12,256]
→ 时间均值 [B,256]
→ 分类器
```

G6只把“时间均值”替换为单头softmax注意力：

```text
score_t = Linear(256, 1, bias=False)
weight_t = softmax(score_t)
pooled = Σ weight_t × hidden_t
```

## 2. 为什么选择零初始化注意力

注意力打分权重初始化为全零，因此每个时间步初始权重为`1/12`，初始输出在预注册浮点容差内与G2的mean pooling数值等价。自定义零初始化层不消耗随机数，G2与G6构模后的CPU RNG状态一致；共享的CNN、GRU和分类器也保持相同seed初始化。

参数变化为：

| 模型 | 参数量 | 增量 |
|---|---:|---:|
| G2 mean pooling | 1,012,193 | — |
| G6 attention pooling | 1,012,449 | +256（+0.0253%） |

`bias=False`是必要约束，因为所有时间步共享的标量bias会在softmax中完全抵消、梯度恒为零。mean+max拼接会增加32,768个分类器参数并可能放大困难负类瞬态；双分辨率Log-Mel需要同时改变前端与首卷积，均不纳入G6。

## 3. 严格冻结项

G6相对G2只允许两个配置差异：

```text
model.temporal_pooling: 缺省mean → attention
output_dir: G2目录 → G6独立目录
```

以下内容逐字段冻结：

- Full DADS manifest及seed 42划分；
- 64-bin Log-Mel全部参数；
- G2声学增强及SNR概率；
- 自然shuffle、每epoch样本量和自动`pos_weight`；
- CNN、BiGRU、分类器、dropout；
- batch size、优化器、学习率、early stopping；
- DADS阈值和val checkpoint选择规则；
- val_ood tune/holdout清单、G2预测及校准结果。

候选配置：`configs/crnn_dads_full_augmented_g6_temporal_attention.yaml`。

## 6. 第一关：历史DADS已消费内部回归非劣

本方案沿用的`dads_all_seed42.csv`先在每个标签内随机把Parquet行（`AudioRef`）
分配到Train、Validation和Test，再把每行展开成1秒片段；同一行的片段不跨split，
但`source_path`不是实际分组键，其零交集只是事后身份审计结果。后验原始WAV字节级
SHA256审计发现15个重复哈希组，共涉及30条Parquet记录；每组保留1条并移除15条，
其中6组成员原本跨至少两个split，连带移除244条历史1秒manifest片段。

该Test还被G6及此前多轮候选门禁读取，因此下文把它限定为“历史DADS同数据源已消费
内部回归集”，不能据此主张来源、会话、设备、场景或型号独立泛化。旧
`dads_dedup_v2`只去掉原始WAV字节级精确重复，仍复用历史1秒`loop/tail_loop`
预处理和缓存，未消除标签相关的时长/重复捷径。后续主实验重跑应改用
`dads_native_half_second_content_component_v2`原生0.5秒内容组件隔离协议。

训练完成后先绑定候选checkpoint、metrics以及DADS val/历史DADS回归集预测数组的SHA256。`metrics.json`还会反向记录checkpoint与四个预测数组的哈希；门控从数组重新计算全部阈值指标，不直接信任JSON中的F1/AUC：

```bash
env PYTHONPATH=src /usr/local/anaconda3/envs/dads-crnn/bin/python -u \
  -m dads_crnn.audit_temporal_pooling_ablation \
  --mode verify

env PYTHONPATH=src /usr/local/anaconda3/envs/dads-crnn/bin/python -u \
  -m dads_crnn.gate_candidate \
  --config configs/g6_temporal_attention_guardrails.yaml \
  --stage internal
```

固定阈值0.50下，DADS Val/历史DADS回归集的F1最大下降0.001；Balanced Accuracy、Recall和Specificity最大下降0.002；AUC最大下降0.0005。任何一项失败立即`keep_g2`。

DADS中`segment_kind`与标签存在明显关联，G2在历史DADS回归集上的正类Recall为：`loop=0.99951`、`full=0.95712`、`tail_loop=0.90286`。这正是旧1秒流程可能暴露标签相关时长/重复捷径的证据；原始WAV精确去重并不能消除它。注意力还可能放大循环拼接边界，因此额外保护：

- DADS Val/历史DADS回归集正类`full` Recall最大下降0.01；
- DADS Val/历史DADS回归集负类`full` Specificity最大下降0.005；
- DADS Val/历史DADS回归集`tail_loop` Recall和Specificity最大下降0.03。

内部失败时不运行val_ood，不通过调阈值或放宽门槛挽救候选。

### 6.1 实际执行结果（2026-07-18）

- 训练正常完成50个epoch，最佳checkpoint来自epoch 40，总耗时约127.20分钟；
- `audit_temporal_pooling_ablation --mode verify`通过，候选checkpoint SHA256为
  `8a2d40278a2b7a70cbddeff869b789711e7805dbfa51cfb8649b48ecf3b68377`；
- 26项自动化测试全部通过；
- 历史DADS已消费内部回归门禁通过，判定为`proceed_to_val_ood`；
- 历史DADS回归集@0.50相对G2：F1 `-0.000088`、Balanced Accuracy `-0.000302`、
  Recall `+0.000735`、Specificity `-0.001339`、AUC `-0.000030`；
- `full`与`tail_loop`片段保护项全部通过。

该结果只说明G6没有突破预设的内部退化保护线，不代表G6已经优于G2。是否晋级仍由下一节的
val_ood严格门禁决定；在最终门禁通过前，G2继续作为当前冠军模型。

## 7. 第二关：val_ood开发集晋级

只有内部关通过才执行一次：

```bash
nohup env PYTHONPATH=src CUDA_VISIBLE_DEVICES=0 \
  /usr/local/anaconda3/envs/dads-crnn/bin/python -u -m dads_crnn.calibrate_ood \
  --checkpoint archive/historical_models/failed_candidates/artifacts_crnn_full_augmented_g6_temporal_attention/runs/seed_42/best.pt \
  --tune-manifest artifacts/val_ood/manifests/val_ood_tune_manifest.csv \
  --holdout-manifest artifacts/val_ood/manifests/val_ood_holdout_manifest.csv \
  --output-dir artifacts/val_ood \
  --experiment crnn_full_augmented_g6_temporal_attention \
  --batch-size 256 --num-workers 0 --device auto \
  --target-recall 0.80 --target-specificity 0.90 \
  > logs/g6_crnn_temporal_attention_seed42_val_ood.log 2>&1 &
echo $!
```

完成后：

```bash
env PYTHONPATH=src /usr/local/anaconda3/envs/dads-crnn/bin/python -u \
  -m dads_crnn.gate_candidate \
  --config configs/g6_temporal_attention_guardrails.yaml \
  --stage final
```

最终门控同时要求：

1. G2/G6 tune与holdout的路径、SHA256、标签、来源组、条件和顺序完全一致；
2. tune/holdout每个实际WAV的当前SHA256与manifest逐文件一致，避免音频在两次评估间漂移；
3. 校准checkpoint、manifest、预测CSV SHA256以及目标Recall/Specificity与预注册配置一致；
4. 从CSV logit重新计算raw/calibrated probability，重新拟合temperature和tune阈值，结果必须与校准JSON一致；
5. holdout F1、Balanced Accuracy、Recall、Specificity和AUC对G2严格点估计Pareto非退化；
6. F1或AUC至少提高0.02，或Recall至少提高0.03；
7. UAV-only、六个SNR条件Recall及背景Specificity最大下降0.02；
8. 正类来源macro Recall、负类来源macro Specificity最大下降0.02；
9. 对同一批G2/G6预测执行2,000次配对multiway Bayesian bootstrap，同时按`uav_source`与`background_source`施加乘法权重，各主指标95%单侧下界不低于-0.02；满足点估计实质提升的同一指标，其bootstrap下界还必须大于0。

通过时只输出`promote_g6_dev_champion`，表示当前开发集上的候选冠军。部署目标`Recall≥0.80且Specificity≥0.90`会单独报告，不是开发冠军晋级的硬条件，也不得被表述为已经达到部署要求。

### 7.1 最终执行结果（2026-07-18）

最终门禁未通过，决策为`keep_g2`，且工具链与数据完整性检查均通过、`errors=[]`；
因此这是候选性能不满足晋级标准，不是执行故障。

| Holdout指标 | G2 | G6 | G6-G2 | 门禁 |
|---|---:|---:|---:|---:|
| F1 | 0.709546 | 0.691218 | -0.018328 | 失败 |
| Balanced Accuracy | 0.708837 | 0.703695 | -0.005142 | 失败 |
| Recall | 0.717808 | 0.668493 | -0.049315 | 失败 |
| Specificity | 0.699865 | 0.738896 | +0.039031 | 通过 |
| AUC | 0.760722 | 0.773325 | +0.012603 | 通过但未达到+0.02实质提升线 |

条件级Recall在`uav_only`、SNR `+10/+5/-10/-15 dB`上超过允许下降幅度，正类来源macro
Recall下降0.045839。2,000次UAV/背景来源双向配对Bootstrap中，F1、Balanced Accuracy和
Recall未通过非劣检验，且没有任何指标同时获得点估计实质提升与正的统计下界。

G6在tune上相对G2的选定阈值指标全面改善，但这种改善没有稳定迁移到holdout；同时holdout
AUC和Specificity提高而Recall明显下降，说明时序注意力增强了部分排序/负类排除能力，却带来
跨来源的分数分布和工作点不稳定。不得根据本次holdout结果事后调整阈值后宣称G6晋级。

## 8. 数据边界和停止规则

当前val_ood holdout已用于多轮方案判断，应视为开发集而非无偏测试集。G6只允许这一种预注册attention形式，不再根据val_ood结果尝试hidden层、bias、mean+max或注意力温度变体。

- 内部失败：停止G6，保留G2；
- val_ood失败：停止G6，保留G2；
- val_ood通过：先运行seed 43/44稳定性确认，但仍只称开发冠军；
- Unseen和Real-world继续锁定，不用于选择；
- 最终泛化结论必须增加新的、来源隔离且从未查看过的确认集。
