# G7数据泄露与结果虚高修整报告

更新日期：2026-08-04

## 1. 修整结论

本轮没有重新训练模型，而是先修正G7数据审计、评价单位、Benchmark名称和晋级门禁。
重新审计后的准确结论为：

1. 当前G7-R6 Train、Model Validation、Calibration和四套Benchmark之间没有发现
   完全相同的最终0.5秒模型输入；
2. Kielce正类与TAU负类存在严重的“数据来源=标签”语料捷径，因此Kielce/TAU结果
   不能作为独立跨域最终性能；
3. G13的58个来源组也全部是单一标签来源组；IDMT和ESC-50只包含负类；
4. 所有当前外部数据都已经被使用，只能称为可重复开发Benchmark；
5. G7-R6在G13和IDMT仍然退化，修整后的自动门禁明确判定不晋级。

## 2. 最终模型输入身份审计

哈希对象不是文件路径或原始WAV，而是评价预处理之后，模型实际读取的16 kHz、0.5秒、
little-endian float32波形。

| 数据角色 | 输入行数 | 唯一输入 | 集合内部重复 |
|---|---:|---:|---:|
| Train | 406,157 | 406,157 | 0 |
| Model Validation | 91,698 | 91,698 | 0 |
| Calibration | 4,480 | 4,480 | 0 |
| Kielce/TAU | 38,126 | 38,126 | 0 |
| G13 | 110,000 | 110,000 | 0 |
| IDMT | 58,692 | 58,687 | 5 |
| ESC-50 | 480 | 480 | 0 |

Train与Model Validation的最终输入交叉为0；Train+Validation与Calibration、
Kielce/TAU、G13、IDMT和ESC-50的交叉也全部为0。IDMT内部5行重复约占0.0085%，
不是训练测试泄漏，不会实质改变当前FPR；后续发布新Benchmark版本时应删除重复代表。

该审计只排除精确等价输入，尚不能排除重编码、增益变化、轻微裁剪或声学近重复。

## 3. 发现的语料捷径

### 3.1 Kielce/TAU

Train中Kielce全部是正类，TAU全部是负类；Benchmark中仍然是Kielce全部正类、TAU
全部负类。只使用Train中的`dataset_origin → label`多数映射，在Benchmark 38,126行上
覆盖率和Accuracy都为1.0。

这不是相同音频泄漏，但模型可能通过设备、背景、动态范围和数据制作方式区分语料，
因此99%左右的切片Accuracy不能直接解释为真实部署性能。

### 3.2 G13

G13共有58个来源组，其中29个正类、29个负类；58个来源组全部只包含一个标签。
它仍可作为跨语料压力测试，但不能排除模型依赖来源条件，不是理想的同设备正负配对测试。

### 3.3 IDMT与ESC-50

两者都是纯负压力集，只能回答背景误报率，不能独立报告完整Accuracy、Recall或F1。
ESC-50 guard还是与训练困难负类相同语料的不同fold，因此只作为同语料机械声门禁。

## 4. 评价单位修整

新版评测同时输出四层结果：

1. 0.5秒切片：仅作为局部诊断；
2. 录音均值：当前主要部署评价单位；
3. 来源组内全部概率均值：检查整个会话的稳定性；
4. 来源组宏平均录音指标：每个会话等权，避免长会话拥有更多切片而支配结果。

固定阈值0.5下的来源组宏平均结果：

| Benchmark | 模型 | 宏Recall | 宏FPR | 宏Balanced Accuracy |
|---|---|---:|---:|---:|
| Kielce/TAU | G7-R2 | 1.0000 | 0.0068 | 0.9966 |
| Kielce/TAU | G7-R6 | 1.0000 | **0.0002** | **0.9999** |
| G13 | G7-R2 | **0.7800** | **0.1314** | **0.8243** |
| G13 | G7-R6 | 0.7453 | 0.1485 | 0.7984 |
| IDMT | G7-R2 | — | **0.1106** | — |
| IDMT | G7-R6 | — | 0.1475 | — |
| ESC-50 | G7-R2 | — | 0.0000 | — |
| ESC-50 | G7-R6 | — | 0.0000 | — |

来源组指标没有改变总体判断：G7-R6的改善集中在Kielce/TAU，同样没有迁移到G13和
IDMT。

## 5. 自动晋级门禁

新版程序不再硬编码结论，而是以来源组宏平均录音指标为主，在固定阈值0.5下检查：

- Kielce/TAU来源组宏Balanced Accuracy不下降；
- Kielce/TAU来源组宏FPR不升高；
- G13来源组宏Balanced Accuracy不下降；
- G13录音级ROC-AUC不下降；
- IDMT来源组宏FPR不升高；
- ESC-50来源组宏FPR不升高。

G7-R6通过Kielce/TAU和ESC-50门禁，但未通过：

```text
g13_group_balanced_accuracy_not_lower
g13_recording_roc_auc_not_lower
idmt_group_fpr_not_higher
```

因此`promoted_on_reusable_benchmark=false`。即使未来所有可重复门禁通过，也只能获得
开发候选资格，独立最终结论仍需要全新未消费数据。

## 6. 本轮代码修整

- `src/dads_crnn/g7_benchmark_validity.py`：来源标签纯度、语料查表捷径和元数据交叉审计；
- `src/dads_crnn/audit_g7_benchmark_validity.py`：最终0.5秒模型输入全量哈希审计；
- `src/dads_crnn/evaluate_g7_r6_external_suite.py`：来源组指标、可信度字段和自动晋级门禁；
- `configs/g7_r6_reuter_reusable_protocol.yaml`：冻结修整后的Benchmark和报告规则；
- `tests/test_g7_benchmark_validity.py`：捷径识别、可信度和晋级门禁测试；
- `bash scripts/run_g7_r6_training.sh audit-validity`：完整审计命令。

## 7. 尚不能通过代码解决的问题

当前没有同一外部语料、同一设备和同一会话下同时采集的无人机与背景数据。因此不能把
Kielce和TAU重新随机组合成无语料捷径的独立测试。真正修复需要新增：

```text
同一地点、日期和设备
├── UAV在场
└── UAV不在场背景
```

新增数据必须按飞行事件/背景会话隔离，并在模型、阈值和报告协议冻结后进入新的
Benchmark版本。当前结果继续保留用于可重复开发比较，不再升级措辞。
