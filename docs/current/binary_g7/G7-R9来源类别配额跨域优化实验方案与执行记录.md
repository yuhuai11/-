# G7-R9来源/类别配额跨域优化实验方案与执行记录

更新日期：2026-09-09

## 1. 当前结论

G7-R9已完成代码实现、配置冻结、单元测试和数据级预检，尚未开始GPU正式训练。

当前运行环境无法与NVIDIA驱动通信，因此不能在本次检查中执行真实GPU前向/反向预检或训练。数据级审计已经通过，不代表模型训练已经完成。

## 2. 为什么进行R9

G7-R7的Frequency MixStyle使G13外部无人机指标提高，但IDMT交通背景误报增加：

| 指标 | 严格基线 | R7 |
|---|---:|---:|
| G13 Recall，1秒/录音级 | 0.783408 | 0.811618 |
| G13 pAUC，FPR≤0.05 | 0.738079 | 0.789265 |
| IDMT FPR | 0.156682 | 0.177707 |

R8直接加入43,320个TAU城市负样本后，IDMT FPR降低到0.098889，但G13 Recall下降到0.739421，pAUC下降到0.733357。

这说明当前问题不是“缺少城市负样本”，而是城市负样本的训练剂量、类别比例和更新次数没有被独立控制。R8同时发生了：

1. 训练集负类数量增加；
2. 每个epoch的优化步数增加；
3. batch中正负比例变化；
4. 城市背景梯度贡献大幅增加。

因此无法只用R8判断合适的城市负样本剂量。

## 3. R9的核心方法

R9保持以下部分与R7一致：

- AudioSet预训练PANNs Cnn14；
- 0.5秒、16 kHz输入；
- 64维Log-Mel前端；
- Frequency MixStyle；
- 频率遮挡；
- 背景混合和结构化麦克风频响增强；
- Adam、学习率、衰减、epoch和早停；
- seed42首轮筛选；
- R7实际使用的`pos_weight=1.1416534670890532`。

R9只引入一个主要变化：**类别/数据域配额BatchSampler**。

每个batch固定为：

```text
Batch size = 128
├─ 无人机正类：60
└─ 背景负类：68
   ├─ DADS背景：按实验剂量分配
   └─ TAU城市背景：按实验剂量分配
```

每个epoch固定为2,282个batch，即292,096个训练样本视图。这样不会因为加入TAU数据而自动增加优化步数。

域内样本使用确定性随机排列，只有所需抽样数超过域内样本数时才进入下一轮排列。R9没有使用IDMT分数挑选困难负样本，也没有按照外部测试结果选择单条训练数据。

## 4. 三条实验臂

| 实验臂 | TAU占负类比例 | 每轮正类 | 每轮DADS负类 | 每轮TAU负类 | 每轮总样本 |
|---|---:|---:|---:|---:|---:|
| `control_00` | 0% | 136,920 | 155,176 | 0 | 292,096 |
| `tau_05` | 5% | 136,920 | 147,417 | 7,759 | 292,096 |
| `tau_10` | 10% | 136,920 | 139,658 | 15,518 | 292,096 |

三条实验臂除TAU负类剂量、协议名称和输出目录外完全一致。

设置0%对照臂非常重要，因为配额采样本身也可能改变结果。比较顺序应为：

1. `control_00`与R7比较：判断固定batch比例和固定步数的影响；
2. `tau_05`与`control_00`比较：判断5%TAU剂量的净作用；
3. `tau_10`与`control_00`比较：判断10%TAU剂量的净作用；
4. 通过全部预注册门槛的候选再与R7比较。

## 5. 数据安全边界

R9复用R8已经审计的训练清单：

`artifacts/g7_r8_urban_negatives/data/manifest.csv`

训练人口为：

| 标签/来源 | 可用训练视图 |
|---|---:|
| DADS背景负类 | 155,685 |
| DADS无人机正类 | 136,368 |
| TAU城市背景负类 | 43,320 |

约束如下：

- TAU只来自预先定义的`train`角色；
- TAU全部为负类；
- TAU不能进入正类背景混合器；
- DADS验证集和内部测试集保持不变；
- G13、IDMT、ESC-50和Kielce/TAU不参与训练、早停或逐样本选择；
- 当前外部集合属于已消费、可重复的开发Benchmark，不能称为新的独立最终测试。

数据级预检产物：

`artifacts/g7_r9_domain_quota/preflight/audit.json`

预检结果为`passed=true`。

## 6. 两阶段晋级规则

### 6.1 内部安全门

候选训练结束后，先读取DADS内部测试结果。相对于R7：

- 0.5秒片段F1下降不超过0.003；
- 录音级F1下降不超过0.003；
- 录音级Recall下降不超过0.005。

任一条件失败，则停止该实验臂，不运行外部Benchmark。

### 6.2 外部开发门

内部安全门通过后，按预先固定的1秒非重叠概率均值和固定阈值0.5评价：

| 指标 | 晋级条件 |
|---|---:|
| IDMT FPR | ≤ 0.156682 |
| G13 pAUC，FPR≤0.05 | ≥ 0.779265 |
| G13 Recall | ≥ 0.801618 |
| G13 ROC-AUC | ≥ 0.946441 |
| ESC-50 FPR | ≤ 0.021667 |
| Kielce/TAU Recall | 相对R7下降不超过0.010 |
| Kielce/TAU FPR | ≤ 0.006536 |

不能用IDMT的大幅提升抵消G13的明显下降。只有全部条件同时通过，才允许训练seed43和44。

## 7. 预测缓存保护

R9外部评价不再只凭数组形状复用预测缓存。缓存身份绑定：

- 候选检查点路径与SHA-256；
- 各外部数据清单路径、SHA-256和行数；
- R9评价代码；
- R7报告代码；
- 外部数据构建代码。

任一身份发生变化，旧预测不允许直接复用。这降低了更换模型或清单后误读旧结果的风险。

## 10. GPU恢复后的执行顺序

先检查GPU与静态审计：

```bash
nvidia-smi
bash scripts/run_g7_r9_domain_quota.sh audit
```

依次执行真实GPU预检：

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/run_g7_r9_domain_quota.sh preflight control_00
CUDA_VISIBLE_DEVICES=0 bash scripts/run_g7_r9_domain_quota.sh preflight tau_05
CUDA_VISIBLE_DEVICES=0 bash scripts/run_g7_r9_domain_quota.sh preflight tau_10
```

建议先训练0%对照，再训练5%和10%剂量：

```bash
CUDA_VISIBLE_DEVICES=0 nohup bash scripts/run_g7_r9_domain_quota.sh train control_00 > logs/g7_r9_control_00_seed42.log 2>&1 &
CUDA_VISIBLE_DEVICES=0 nohup bash scripts/run_g7_r9_domain_quota.sh train tau_05 > logs/g7_r9_tau_05_seed42.log 2>&1 &
CUDA_VISIBLE_DEVICES=0 nohup bash scripts/run_g7_r9_domain_quota.sh train tau_10 > logs/g7_r9_tau_10_seed42.log 2>&1 &
```

如果只有一张GPU，不要同时运行三条训练，应等待前一条结束后再运行下一条。

训练意外中断时恢复：

```bash
CUDA_VISIBLE_DEVICES=0 nohup bash scripts/run_g7_r9_domain_quota.sh resume tau_05 > logs/g7_r9_tau_05_seed42.log 2>&1 &
```

查看状态：

```bash
bash scripts/run_g7_r9_domain_quota.sh status
tail -f logs/g7_r9_tau_05_seed42.log
```

某实验臂内部安全门通过后运行外部评价：

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/run_g7_r9_domain_quota.sh external control_00
CUDA_VISIBLE_DEVICES=0 bash scripts/run_g7_r9_domain_quota.sh external tau_05
CUDA_VISIBLE_DEVICES=0 bash scripts/run_g7_r9_domain_quota.sh external tau_10
```

外部评价程序会在内部安全门失败时主动停止，避免不必要地读取外部Benchmark。
