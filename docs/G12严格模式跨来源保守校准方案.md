# G12 严格模式跨来源保守校准方案

## 1. 目标

G11 最终测试表明，G9 三种子集成在低误报区域具有更高检出能力，但 G10 严格阈值只覆盖了调参集约 90% 的背景来源，迁移到 Unseen 后出现小幅 FPR 增长。G12 不更换模型、不继续读取最终测试数据，只修正严格模式的跨来源阈值策略。

G12 的目标是：在未参与拟合的 `val_ood holdout` 上，相对 G7 同时满足 FPR 不增加、TPR 不降低、F1 不降低，并保持来源宏平均指标不退化。

## 2. 冻结策略

- 候选模型：G9 PANNs Cnn14_16k AudioSet 三种子（42、43、44）原始 logit 算术平均。
- 温度：复用 G10 在 `val_ood tune` 上冻结的温度，不读取 holdout 或最终测试集拟合。
- 工作模式：只推进严格模式，目标 FPR 为 1%。
- 平衡模式：继续使用 G7，不再使用 G11 的 pooled 阈值。
- 来源字段：`background_source`。
- 来源覆盖目标：95%。调参集有 25 个负类来源，对应顺序统计量秩为 25，实际可估计覆盖下界为 `25 / 26 = 96.15%`。
- 阈值：25 个来源局部 1% FPR 阈值中的最大值。
- 召回保护：相对 pooled 1% 阈值，调参集 TPR 保留率不得低于 80%。

## 3. 数据隔离

拟合只允许读取：

- `val_ood tune` 清单；
- G9 三种子的 tune 预测；
- G10 冻结校准文件。

评估阶段才允许读取 `val_ood holdout`。以下数据禁止用于 G12 拟合、阈值选择或代码调试：

- `unseen_manifest.csv`；
- `real_world_manifest.csv`；
- G11 最终预测和指标。

现有 Unseen 与 Real-world 已经消耗，只能作为历史证据，不能再次用于选择 G12 阈值。G12 若通过内部 holdout，只能进入“等待新外部集确认”状态。

## 4. 晋级门槛

相对 G7 的 `val_ood holdout` 严格模式，以下项目必须全部通过：

1. FPR 不增加；
2. TPR 不降低；
3. F1 不降低；
4. UAV 来源宏平均 TPR 不降低；
5. 背景来源宏平均 FPR 不增加；
6. ROC-AUC、PR-AUC、低 FPR Partial-AUC 均不降低。

通过后的状态为 `strict_candidate_ready_for_new_external_confirmation`，不是正式部署晋级。

## 5. 运行顺序

```bash
cd /home/user1/JJZ/ABDDV-CRNN
mkdir -p logs

bash scripts/run_g12_strict_calibration.sh fit \
  2>&1 | tee logs/g12_strict_fit.log

bash scripts/run_g12_strict_calibration.sh evaluate \
  2>&1 | tee logs/g12_strict_evaluate.log
```

该阶段仅处理已有预测文件，不需要 GPU，也不需要后台长时间运行。

## 6. 后续边界

如果 G12 通过内部 holdout，下一步应准备新的独立外部确认集，并在读取前冻结确认协议。如果 G12 未通过，则停止阈值校准路线，转入训练集内的交通类困难负样本补充和 UAV 机型均衡；不得使用已经消耗的最终测试样本进行训练或阈值搜索。
