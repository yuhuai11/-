# G18基于G7的分层开放集无人机型号识别方案

## 1. 目标

在不破坏正式G7二分类检测器的前提下，将工程扩展为：

```text
前端声学信号
  ↓
信号质量与有效性检测
  ↓
G7：无人机/非无人机检测
  ↓ 仅当检测为无人机
G18：型号识别
  ↓
具体型号 / Unknown UAV
```

G18是开发候选，不自动替代G7。G7继续负责低误报的无人机存在检测；G18只处理
G7判定为无人机的片段。

## 2. 当前能力边界

G7训练标签只有`0=背景、1=无人机`，不能直接输出具体型号。G18复用G7二分类头前的
2048维embedding，并增加独立机型分类头：

```text
G7 PANNs Cnn14_16k
  ├─ 原二分类头：保持冻结
  └─ 2048维embedding → LayerNorm → 9类Linear Head
```

初始阶段只训练约1.8万参数的机型头，G7约7996万参数全部冻结。这样可以：

- 保持正式G7检测能力不变；
- 降低小数据训练造成的灾难性遗忘；
- 快速判断G7 embedding是否包含型号信息；
- 为后续G17高频embedding融合保留接口。

## 4. 数据隔离

原G14划分面向二分类，并不适合型号识别。多数型号只对应一个采集来源组，直接沿用会
导致某些型号只出现在训练集或只出现在留出集。

G18-P0采用独立的原始录音级划分：

```text
split_unit = raw_audio_sha256
```

同一原始录音的全部一秒片段只能属于一个分区。每条原始录音最多保留20个均匀位置
片段，防止长录音支配训练。

P0实际生成：

| 分区 | 片段 | 原始录音 | 用途 |
|---|---:|---:|---|
| known_train | 8,080 | 404 | 训练分类头 |
| known_tune | 1,820 | 91 | 早停和已知类校准 |
| known_holdout | 1,820 | 91 | 已知型号开发留出 |
| unknown_tune | 1,800 | 90 | Unknown阈值选择 |
| unknown_holdout | 1,780 | 89 | Unknown开发留出 |

五个分区的原始音频SHA256交集全部为0，已消费G13哈希重叠为0，封存测试集读取为空。

## 5. 分层推理规则

对于每个时间窗：

```text
if G7无人机概率 < detection_threshold:
    输出 Background
else:
    计算9类型号概率
    if 最大型号置信度 < known_confidence_threshold:
        输出 Unknown UAV
    else:
        输出具体型号
```

`known_confidence_threshold`不能主观指定，必须使用`known_tune + unknown_tune`选择，
随后冻结并仅在`known_holdout + unknown_holdout`评估一次。

正式前端使用时应聚合连续3～10秒，而不是依赖单个一秒片段：

```text
逐窗口G7门控
→ 有效无人机窗口embedding
→ 原始录音级平均logit或多数投票
→ Unknown门控
→ 型号与置信度
```

## 6. 评价指标

### 6.1 已知型号

- Segment Macro-F1；
- Recording Macro-F1；
- 每型号Precision、Recall、F1；
- 混淆矩阵；
- 最差型号Recall；
- Top-1与Top-3准确率。

### 6.2 Unknown拒识

- Known/Unknown AUROC；
- Unknown Recall；
- 已知型号误拒率；
- 未知型号误接纳率；
- OSCR；
- FPR@95% Unknown TPR。

### 6.3 完整链路

- Background → UAV误报率；
- UAV → Background漏检率；
- 已知型号端到端正确率；
- Unknown UAV正确拒识率；
- 录音级延迟和多窗口稳定性。

## 7. 晋级门槛

seed 42可行性训练建议门槛：

- G7检查点哈希保持不变；
- G7全部参数无梯度；
- 已知类Recording Macro-F1明显高于随机基线；
- 每个已知型号Recall均有报告，不允许只给总体Accuracy；
- Unknown Holdout AUROC和Unknown Recall通过预注册下限；
- 型号预测不得绕过G7背景门控；
- 不读取Unseen、Real-world或G13。

seed 42证明可行后才运行42、43、44三种子。三种子稳定后仍只能称为Kielce同设备开发
结果，不能宣称真实跨设备型号识别已经完成。

## 8. 当前局限

Kielce型号录音全部来自`OLYMPUS_LS11`，且多数型号只有单一采集会话。因此当前结果
可能学习：

- 采集日期和环境；
- 型号对应的固定距离组合；
- 同一架无人机的个体声纹；
- 单一麦克风频响；
- 数据制作流程。

原始录音级隔离能防止相邻片段泄漏，但不等于跨设备、跨地点、跨无人机个体泛化。
要满足真实前端部署目标，后续仍需采集：

- 每型号至少多个物理个体；
- 多种麦克风；
- 多地点和多背景；
- 多距离、高度和姿态；
- 未参与训练的新型号；
- 与实际前端完全一致的采样率、增益和编码链路。

### 12.1 训练协议

- G7全部参数冻结；
- G7保持`eval()`，BatchNorm缓冲区逐轮验证不变；
- 只训练LayerNorm和9类Linear Head，共22,537参数；
- 每轮每型号自然无放回抽取620个片段；
- 每轮总计5,580个类均衡片段；
- Batch size 128；
- AdamW，学习率0.001；
- label smoothing 0.05；
- gradient clipping 5.0；
- 最多25轮，patience 5；
- 使用`known_tune`录音级Macro-F1早停；
- 同分时使用片段级Macro-F1决定；
- 不运行外部测试。

### 12.2 可行性门槛

只有最佳Tune结果同时满足：

```text
recording_macro_f1 >= 0.50
recording_minimum_recall >= 0.20
```

才允许进入Unknown阈值校准。这里的门槛只用于判断分支是否具有基础可行性，不代表
部署性能合格。
