# G14 多来源域泛化开发方案

## 执行状态（2026-07-23）

- P0数据防火墙与DADS去重审计已完成；
- NASA Small UAS官方压缩包已下载并完成SHA256/ZIP结构审计；
- NASA共识别46个UAV正类flight与16个固定翼困难负类flight；
- NASA许可证表达仍未归档明确，训练门控保持关闭；
- TAU元数据及第16分卷已通过完整性审计；
- TAU第16分卷仅覆盖tram场景和8个来源组，禁止单独接入；
- TAU第1、9、16分卷均已完成完整性校验；
- 三分卷联合得到33,894条音频、63个来源组、3个场景、10个城市及9种设备；
- TAU覆盖门控已解除，当前唯一训练阻塞项为NASA许可证表达未明确。

## 1. 背景与方向修正

G13 一次性外部确认表明，G9/G12 困难负类适配没有迁移到新的真实外部域。候选不仅在固定阈值下同时增加误报和漏报，ROC-AUC、PR-AUC 与低 FPR pAUC 也全部下降。

因此 G14 不再沿用“继续增加相同来源困难负类”的路线，而将主要问题定义为：

> 如何在保留 G7 广泛预训练能力的同时，提高跨设备、跨录音会话和跨环境的来源级泛化能力。

G14 是新的开发阶段，不是 G13 的重试。G13、旧 Unseen 和旧 Real-world 均属于已消费最终数据，不能进入 G14 的训练、校准、模型选择或集成权重选择。

## 2. 当前基线

G14 的唯一基线为 G7：

- 模型：PANNs Cnn14_16k；
- 检查点：`artifacts_g7_panns_pt/runs/seed_42/best.pt`；
- 严格模式继续使用 G7；
- 平衡模式继续使用 G7；
- G12 只保留为失败候选的研究记录，不作为 G14 初始化的默认选择。

## 3. 数据隔离原则

### 3.1 永久禁止用于开发的数据

- `data/external_confirmation_v2/`；
- `artifacts/g13_external_confirmation/` 中的 manifest、predictions 和 metrics；
- 旧 Unseen；
- 旧 Real-world；
- 任何由上述音频复制、重命名、转码或派生的文件。

允许对这些数据进行的操作仅限于：

- 读取已生成的最终报告；
- 核验封存哈希；
- 论文中报告一次性最终结果。

### 3.2 G14 新开发数据要求

G14 必须接入与 G13 不同来源的新开发数据，至少满足：

- 背景和 UAV 均包含多个独立录音来源；
- 能够识别数据集、设备、录音会话或场景来源；
- 来源组之间可以严格隔离；
- 音频许可证允许当前研究用途；
- 所有音频具有 SHA256；
- 与 DADS、G9困难负类、G13及旧最终集进行哈希排重。

### 3.3 来源隔离划分

新数据不得随机按音频片段划分。应按完整来源组划分：

- `train_sources`：模型训练；
- `tune_sources`：温度、阈值及有限超参数选择；
- `holdout_sources`：开发阶段唯一模型门槛；
- 同一设备、录音会话或原始长录音不得跨集合。

在 G14 开发完成后，还需另行准备从未读取的新最终确认集。G13 不得再次承担这一角色。

## 4. G14 分阶段实验

### 阶段 P0：数据防火墙与封存

目标：

- 将 G13 标记为 `consumed_and_closed`；
- 在 PANNs 训练、困难负类准备、BEATs准备和来源稳健校准入口中拒绝 G13 路径；
- 对常见路径变体和 manifest 行内容增加自动测试；
- 保持 G13最终结果文件不变。

通过条件：

- 所有隔离测试通过；
- G13 路径无法被训练或校准入口打开；
- G13 报告和最终指标 SHA256 保持一致。

### 阶段 P1：新开发集接入

目标：

- 选择与 AeroSonicDB、DDL Real Data 不同的新来源；
- 建立统一 source registry；
- 完成格式、时长、来源、许可证、重复和已知数据重叠审计；
- 只生成数据清单，不进行模型训练。

建议最低门槛：

- 每类不少于 10 个来源组；
- 每个来源组不少于 50 条有效片段；
- 背景包含机械、交通、风噪、安静环境等条件；
- UAV包含至少两种设备或距离/环境条件；
- 训练、tune、holdout 来源完全不重叠。

### 阶段 P2：G7 来源级诊断

先不训练新模型，使用冻结 G7 对 G14 开发数据生成预测，并回答：

1. 哪些背景来源产生主要误报；
2. 哪些 UAV 来源产生主要漏报；
3. 误差是否集中于设备、场景、信噪比或机型；
4. 来源宏指标与样本级指标差异多大；
5. 是否存在某些来源占据大量样本、掩盖其他来源退化。

P2 只使用 G14 开发数据，不读取任何已消费最终集。

### 阶段 P3：保守适配基线

优先实验为“保留 G7 表示”的保守适配，而不是全网络大幅微调：

#### G14-A：冻结主干，仅训练分类头

- 使用 G7 初始化；
- 冻结卷积主干；
- 仅训练最终分类层；
- 按来源均衡采样；
- seed 42、43、44。

目的：验证仅调整决策层能否适应新开发域，同时最大程度保留 AudioSet 预训练表示。

#### G14-B：解冻最后一个卷积块

仅当 G14-A 在开发 holdout 上通过门槛时执行：

- 解冻最后一个卷积块和分类头；
- 主干其他部分保持冻结；
- 使用低于原训练的学习率；
- 加入权重衰减和早停；
- seed 42、43、44。

目的：在有限表示适配与避免灾难性遗忘之间取得平衡。

#### G14-C：来源与设备扰动

仅当 P2 证明误差与录音设备或环境响应显著相关时执行：

- 频率响应扰动；
- 增益与动态范围扰动；
- 轻量背景混合；
- 混响和带宽限制；
- 来源均衡采样。

不得一次引入多种无法单独归因的增强。每种增强必须做独立消融。

## 5. 模型选择目标

G14 不以单一 F1 或 accuracy 选择模型。开发 holdout 上必须同时报告：

- 总体 FPR；
- 总体 TPR；
- F1；
- 背景来源宏平均 FPR；
- UAV 来源宏平均 TPR；
- 最差背景来源 FPR；
- 最差 UAV 来源 TPR；
- ROC-AUC；
- PR-AUC；
- `FPR ≤ 0.05` 标准化 pAUC；
- 来源组 Bootstrap 置信区间。

推荐采用词典序约束：

1. 首先要求背景来源宏平均 FPR 不高于 G7；
2. 同时要求 UAV 来源宏平均 TPR 不低于 G7；
3. 然后比较低 FPR pAUC；
4. 最后才比较总体 F1。

任何通过降低 TPR 换取 FPR、或通过提高 FPR 换取 TPR 的候选，都不能自动晋级。

## 6. 开发阶段继续门槛

候选必须在三个种子上分别完成训练，并同时满足：

- 三种子均无 NaN/Inf；
- 三种子来源宏指标方向一致；
- 三种子平均总体 FPR不高于 G7；
- 三种子平均总体 TPR 不低于 G7；
- 三种子平均背景来源宏 FPR 不高于 G7；
- 三种子平均 UAV 来源宏 TPR 不低于 G7；
- 三种子平均低 FPR pAUC 不低于 G7；
- 最差种子不能出现明显退化。

如果 G14-A 未通过，不直接扩大搜索范围；应先分析失败来源，再决定是否有证据进入 G14-B 或 G14-C。

## 7. 防止再次走偏的约束

G14 明确禁止：

- 在一个来源上反复挖困难负类并据此宣称泛化提升；
- 使用样本随机划分代替来源隔离；
- 只看总体准确率；
- 根据 holdout 结果进行无上限网格搜索；
- 使用 G13 选择增强、学习率、冻结层数或阈值；
- 在同一最终确认集失败后调参复测；
- 在没有新最终确认集的情况下宣称候选可部署。

## 10. 确定执行计划

G14 按以下单向流程执行：

```text
封存 G13
  -> 建立数据防火墙
  -> 生成 DADS 去重审计版本
  -> 接入新的多来源开发数据
  -> 冻结 G7 做来源级诊断
  -> G14-A 仅训练分类头
  -> 有证据时执行 G14-B 或 G14-C
  -> 冻结唯一候选
  -> 使用全新最终集做唯一一次测试
```

任何阶段未达到继续门槛时，在该阶段停止并分析原因，不允许通过读取已消费最终数据、扩大无上限搜索或反复测试最终集来推进。

### 10.1 阶段一：数据防火墙与基线固定

这是当前首先执行的阶段。

工作内容：

1. 将 G13 状态固定为 `consumed_and_closed`；
2. 保存 G13 最终协议、指标、预测和完成标记的 SHA256；
3. 在训练、数据准备、阈值校准和模型选择入口中拒绝以下内容：
   - `data/external_confirmation_v2/`；
   - `artifacts/g13_external_confirmation/` 中的 manifest、预测和指标；
   - 旧 Unseen；
   - 旧 Real-world；
   - 上述数据复制、重命名、软链接、转码或派生后的路径；
4. 增加路径、manifest 行内容和路径变体测试；
5. 固定 G7 为唯一开发基线：
   - 模型：PANNs Cnn14_16k；
   - checkpoint：`artifacts_g7_panns_pt/runs/seed_42/best.pt`；
   - checkpoint SHA256：`d357f194105ec27a61838e0f4c2e7575932e2dd861e529ef970b1fb467954cdc`；
6. G12 仅保留为失败研究记录，不作为 G14 默认初始化。

阶段产物：

```text
artifacts/g14_domain_generalization/p0_firewall/
├── baseline_lock.json
├── consumed_datasets.json
├── g13_hash_inventory.json
└── test_report.json
```

通过条件：

- G13 最终文件哈希保持不变；
- 所有防火墙测试通过；
- 任一开发入口读取已消费数据时均明确失败；
- G7 基线 checkpoint、温度和工作阈值可以由锁定文件唯一恢复。

### 10.2 阶段二：DADS 去重审计版本

该阶段不删除、不覆盖历史 DADS manifest，不修改既有 G7、G9、G12 和 G13 结果。新版本命名为 `dads_dedup_v2`。

工作内容：

1. 对 DADS 原始录音计算 SHA256；
2. 将相同原始音频统一归入同一 `recording_group`；
3. 输出重复组及跨 split 重复明细；
4. 每个重复SHA组只保留一个确定性代表，非重复来源和被保留代表继续使用原split，
   不对全部来源重新划分；
5. 选择重复组代表时，优先维持原有类别与split数量比例；
6. 输出新旧样本量、类别比例、来源比例和去重差异；
7. 检查 `source_path`、原始音频 SHA256 和来源组在三个 split 之间均无交叉。

阶段产物：

```text
artifacts/dads_dedup_v2/
├── source_registry.csv
├── duplicate_groups.csv
├── train_manifest.csv
├── val_manifest.csv
├── test_manifest.csv
└── audit.json
```

通过条件：

- 原始音频 SHA256 跨 split 重叠为 0；
- `recording_group` 跨 split 重叠为 0；
- manifest 中不存在缺失音频；
- 新旧数据差异有完整审计记录；
- 历史 manifest 和历史实验结果未被改写。

该阶段仅治理原始WAV精确重复，不自动触发G7重训。`dads_dedup_v2`保留历史1秒
loop/tail-loop缓存，因此没有消除后来发现的类别相关时长捷径，也没有按最终float32
或PCM16模型输入建立内容组件。其`test`只能作为已消费的内部回归划分，不能作为新候选
泛化能力或独立最终测试的证据。

后续新增的`dads_native_half_second_content_component_v2`是另一套协议：它重新
解码原始WAV、只保留完整原生0.5秒窗口，并按最终模型输入内容组件重新划分。两种
“v2”不得混写。

### 10.3 阶段三：G14 多来源开发集接入

G14 开发数据必须来自不同于 G13 AeroSonicDB 和 DDL Real Data 的新来源。

最低要求：

- UAV 和背景每类不少于 10 个独立来源组；
- 每个来源组原则上不少于 50 个有效片段；
- 优先包含两个或以上数据集或采集体系；
- UAV包含至少两种机型、距离或环境条件；
- 背景包含机械、交通、风噪、安静环境及其他易混淆声音；
- 可以保留数据集、设备、场景、会话、距离和机型元数据；
- 许可证允许当前研究和论文使用；
- 与 DADS、G9、G13、旧 Unseen 和旧 Real-world 完成 SHA256 排重。

来源组划分为：

- `train_sources`：允许进入模型训练；
- `tune_sources`：允许用于早停、温度、阈值和有限超参数选择；
- `holdout_sources`：只用于开发阶段晋级判断；
- `final_sources`：不进入当前开发流程，留给冻结后的唯一最终评估。

同一原始长录音、设备会话或能够相互派生的音频不得跨集合。

阶段产物：

```text
artifacts/g14_domain_generalization/intake/
├── manifest.csv
├── source_registry.csv
├── duplicate_report.csv
├── license_inventory.csv
└── audit.json

artifacts/g14_domain_generalization/splits/
├── train_sources.csv
├── tune_sources.csv
└── holdout_sources.csv
```

通过条件：

- 所有样本都具有标签、来源组和 SHA256；
- train、tune、holdout 三者来源组交叉为 0；
- 与所有已消费最终数据的已知哈希重叠为 0；
- 类别和来源数量达到最低要求；
- 审计期间没有运行模型预测。

### 10.4 阶段四：冻结 G7 的来源级诊断

在训练任何 G14 候选之前，先使用冻结 G7 对 G14 开发数据生成一次基线预测。

必须回答：

1. 哪些背景来源产生主要误报；
2. 哪些 UAV 来源产生主要漏报；
3. 错误是否集中在设备、距离、场景、风噪、信噪比或机型；
4. 总体指标与来源宏平均指标是否一致；
5. 是否存在大来源掩盖小来源退化；
6. 固定 G7 阈值和在 tune 上重新校准的结果分别如何。

固定阈值结果用于衡量直接迁移能力；tune 校准结果仅用于区分“阈值偏移”和“表征失效”，不得用 holdout 拟合阈值。

阶段产物：

```text
artifacts/g14_domain_generalization/baseline/
├── predictions/
├── overall_metrics.json
├── source_metrics.csv
├── error_cases.csv
└── diagnostic_report.md
```

### 10.5 阶段五：G14-A 分类头适配

G14-A 是唯一默认启动的正式候选。

训练策略：

- 从冻结 G7 checkpoint 初始化；
- 冻结全部卷积主干；
- 仅训练最终分类头；
- 训练输入为`DADS dedup v2 train + G14 train_sources`；这里的DADS输入特指当时的
  raw-WAV去重版和历史1秒缓存，不是后来的原生0.5秒协议；
- 使用来源均衡采样，避免大来源支配梯度；
- seeds 为 42、43、44；
- tune 仅用于早停、温度和阈值；
- holdout 不参与梯度更新、早停或超参数选择；
- 每个种子保存配置、输入 manifest SHA256、checkpoint SHA256 和训练摘要。

G14-A 必须同时接受两类检查：

1. 新域检查：G14 holdout；
2. 回归检查：DADS dedup v2历史`test`（已消费内部回归）和现有Val-OOD开发回归集。

现有 Val-OOD 已被多轮开发使用，只能作为回归集，不能作为新的独立最终证据。

G14-A 继续条件：

- 三个种子均无 NaN/Inf；
- 三个种子的来源宏指标方向一致；
- G14 holdout 平均总体 FPR 不高于 G7；
- G14 holdout 平均总体 TPR 不低于 G7；
- 背景来源宏平均 FPR 不高于 G7；
- UAV来源宏平均 TPR 不低于 G7；
- 低 FPR pAUC 不低于 G7；
- 最差种子和最差来源没有明显退化；
- DADS及 Val-OOD 回归指标没有实质性下降。

如果 G14-A 未通过，先生成失败来源分析，不直接扩大模型、增加种子或进行大范围超参数搜索。

### 10.6 阶段六：有限解冻或针对性增强

本阶段不是必做阶段，只有 P2/P3 结果提供明确证据时才允许执行。

#### G14-B：最后卷积块有限解冻

允许条件：

- G14-A 已优于或至少不劣于 G7；
- 仍存在跨多个 UAV 来源的一致性漏检；
- 诊断表明问题不能仅由阈值重新校准解决。

约束：

- 只解冻最后一个卷积块和分类头；
- 学习率低于分类头训练；
- 使用权重衰减、早停和三种子复验；
- 必须继续执行新域与旧域双重回归门槛。

#### G14-C：来源与设备扰动

允许条件：

- 误差与设备频响、带宽、动态范围、混响或环境噪声存在明确关联。

候选增强包括：

- 频率响应扰动；
- 麦克风带宽限制；
- 增益与动态范围扰动；
- 轻量混响；
- 轻量背景混合。

每次只引入一种可归因增强并保留独立消融。不得一次叠加多种增强后仅报告最终最好结果。

### 10.7 阶段七：候选冻结与唯一最终测试

开发阶段最终只允许选出一个候选。冻结内容包括：

- checkpoint及SHA256；
- 预处理参数；
- 温度和阈值；
- 推理代码版本；
- 输入数据版本；
- 评价指标；
- 预先确定的晋级规则。

冻结完成后，才准备与所有开发数据来源独立的新最终确认集。最终集不得用于训练、早停、阈值、温度、增强选择、冻结层数选择或集成权重选择。

最终评估只运行一次，决策只有：

- `promote`：候选在预先冻结的核心指标上稳定优于或不劣于 G7；
- `do_not_promote`：任一核心泛化指标明显退化，继续保留 G7。

G13 不得重新承担最终确认角色。

## 11. 统一评价与停止规则

每个正式候选必须报告：

- FPR、TPR、Precision、F1和Balanced Accuracy；
- ROC-AUC、PR-AUC；
- `FPR <= 0.05` 标准化 pAUC；
- 背景来源宏平均 FPR；
- UAV来源宏平均 TPR；
- 最差背景来源 FPR；
- 最差 UAV 来源 TPR；
- 来源组 Bootstrap 95%置信区间；
- 三种子均值、标准差和最差种子。

停止规则：

1. 新域 FPR和TPR同时退化：立即停止该候选；
2. 排序指标和阈值指标同时退化：判定为表征泛化失败，不做阈值补救；
3. 只有总体指标提升、来源宏指标退化：不得晋级；
4. 只有一个种子提升：不得晋级；
5. 旧域回归明显退化：不得替换 G7；
6. G14-A 失败且没有明确域偏移证据：不进入 G14-B/C；
7. 最终集一经读取即标记为 consumed，不允许调参后重试。
