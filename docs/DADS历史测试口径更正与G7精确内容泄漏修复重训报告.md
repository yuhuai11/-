# DADS历史测试口径更正与G7精确内容泄漏修复重训报告

> 本文统一说明当前工程的DADS二分类数据、历史G7结果和精确内容泄漏修复实验。
> 历史数值保留用于追溯，但凡与本文冲突的“独立测试”“严格来源隔离”或
> “严格零交叉”表述，均以本文为准。

## 1. 先给出结论

历史G7的DADS高指标不能继续解释为独立测试性能，原因有三项：

1. 历史流程按Parquet行（`AudioRef`）分配，同一行的片段不跨split；`source_path`
   交集为0只是后验结果，不是程序的显式分组规则；
2. 后验审计发现15个精确重复原始WAV SHA组，共涉及30条记录并移除15条重复记录；
   其中6组的成员分布在至少两个split；
3. 历史Test已经被G2—G9等多轮候选晋级和回归门禁使用，不再是未观察的最终测试集。

此外，历史1秒预处理存在明显的类别相关时长捷径。在只做原始WAV精确去重的
`dads_dedup_v2`中：

| 标签 | 原始录音数 | 恰好8000点（0.5秒） | 占比 |
|---|---:|---:|---:|
| 非无人机（0） | 16,715 | 2 | 0.0120% |
| 无人机（1） | 163,590 | 162,000 | 99.0281% |

历史流程把不足1秒的录音循环补齐到16000点，因此“是否由0.5秒内容重复得到1秒”
几乎等价于类别标签。仅用`original_samples == 8000`这个不读取声音内容的规则，在
历史Test上就能得到：

| 指标 | 数值 |
|---|---:|
| Accuracy | 0.936480 |
| Precision | 1.000000 |
| Recall | 0.892914 |
| F1 | 0.943428 |
| TP / FP / TN / FN | 24,306 / 0 / 18,670 / 2,915 |

这不能证明旧G7完全依赖该捷径，但足以证明旧协议无法排除这种解释。因此本轮不是简单
删除几个重复文件，而是从原始WAV重新定义模型输入和划分协议。

按新协议完成的seed 42重训，在固定阈值0.50下得到Val F1 `0.990233`、已消费内部
开发Test F1 `0.988123`。这个结果说明模型在精确内容组件保护后的DADS同数据源数据上
仍有较强区分能力，但不恢复“独立最终测试”或“跨设备泛化”的旧结论。

## 2. 统一术语

| 旧表述 | 当前统一表述 |
|---|---|
| DADS独立测试集 | 历史DADS同数据源已消费内部回归集 |
| DADS来源隔离Test | 按Parquet行分配、`source_path`事后交集为0的历史内部回归集 |
| 来源严格零交叉 | 行标识及事后`source_path`交集为0；后验发现精确音频内容跨split重复 |
| 最终Test | 已参与多轮门禁的内部开发Test |
| 修复后的独立最终测试 | 内容分组保护的内部开发测试，不是新采集最终Holdout |

新协议中的`test`字段为兼容现有训练程序而保留，但其角色被固定为：

```text
consumed_internal_development_test
```

它可以用于同数据源内部回归和修复前后诊断，不能用于声称跨会话、设备、场景、距离或
无人机型号泛化。

### 2.1 两种“v2”不是同一数据协议

| 名称 | 实际作用 | 没有解决的问题 |
|---|---|---|
| `dads_dedup_v2` | 对历史清单中的原始WAV字节做SHA256去重；每组保留一个代表，并保留代表原来的split和历史1秒缓存 | 没有全局重划split，没有审计最终模型输入，也没有消除loop/tail-loop时长捷径 |
| `dads_native_half_second_content_component_v2` | 重新解码原始WAV，只构造完整原生0.5秒窗口，并按原始音频、float32和PCM16等价输入形成不可拆分组件 | 仍不能排除近重复以及未知会话、设备、场地或机体关联 |

因此，旧raw-WAV去重版是输入审计的第一步，不能简称为“已经修复泄漏的严格重训版”。
下文的“新协议”专指`dads_native_half_second_content_component_v2`。

## 3. 为什么旧的“source_path不交叉”仍不能防止内容泄漏

历史程序先对Parquet行做随机分配，`source_path`没有作为显式分组键；当前已知的
`source_path`零交叉来自清单完成后的集合检查。更重要的是，`source_path`只是数据
记录中的标识，不是声音内容本身。两个路径不同的文件仍可能包含完全相同的WAV字节，
两个WAV字节不同的文件也可能在解码、重采样、归一化和补齐后形成相同的模型输入。

因此需要分别检查：

1. 原始WAV字节SHA256；
2. 原始录音组；
3. 模型实际读取的float32波形SHA256；
4. 量化到PCM16后的等价波形SHA256；
5. 由上述相同关系传递形成的连通组件。

只检查路径或AudioRef，最多能证明“同一条清单记录没有直接跨split”，不能证明模型
没有在训练阶段看到验证或测试阶段的等价内容。

## 4. 新协议从头到尾如何构造

新协议名称：

```text
dads_native_half_second_content_component_v2
```

完整流程如下：

```mermaid
flowchart LR
    A["DADS原始Parquet/WAV"] --> B["raw-WAV SHA256去重"]
    B --> C["解码、单声道、16 kHz"]
    C --> D["只保留完整8000点原生窗口"]
    D --> E["删除静音/退化窗口"]
    E --> F["峰值归一化"]
    F --> G["float32与PCM16双哈希"]
    G --> H["相同源/原始音频/最终输入并查集组件"]
    H --> I["跨标签相同内容隔离"]
    I --> J["组件不可拆分划分"]
    J --> K["每类有效录音数与唯一窗口数联合平衡"]
    K --> L["Train / Val / 已消费内部开发Test"]
```

关键约束：

- 输入统一为8000点，即16 kHz下的原生0.5秒；
- 基础窗口构造不允许用loop、tail-loop、repeat、zero-pad、镜像填充或时间拉伸把
  短录音补成0.5秒；
- 不足8000点的录音和不足8000点的尾部统一丢弃；
- 相同原始音频或相同最终输入必须进入同一个`split_component`；
- 相同内容若出现标签冲突，整组隔离，不允许自动选择一个标签；
- PCM16等价输入只保留一个确定性代表；
- 每个标签内同时约束有效`source_id`数量和唯一模型输入数量；
- 最大绝对划分比例误差冻结为0.001，即0.1个百分点；
- Test不参与梯度、早停或阈值选择。

## 5. 为什么选择原生0.5秒

PANNs Cnn14_16k可以直接接受`[batch, 8000]`波形，并继续加载官方AudioSet预训练
权重。采用原生0.5秒有三个直接好处：

1. 所有类别使用同一种真实输入规则，不再让“是否循环重复”泄漏标签；
2. 基础窗口不因长度补齐制造静音边界、重复接缝或时间拉伸造成的人工频率变化；
3. 训练和部署都可以按连续0.5秒窗口执行，定义一致。

代价是PANNs深层时间维度更短，模型更偏向频谱纹理而不是长时间结构。首轮修复实验
不同时改网络池化结构，避免把“数据协议修复”和“模型结构改动”混为一个变量；后续如
需优化，可单独消融减少一次时间池化。

训练阶段仍保留随机时间平移增强。平移造成的空缺边界使用补零，但它只发生在Train，
并以相同规则随机作用于两个类别，不是依据原始录音长度决定的循环补齐，也不会恢复旧
协议中的类别相关时长捷径。

## 7. 分配器错误版本为何被拒绝

分配器经历了三个阶段，不能把前两个失败原因混写：

### 7.1 尝试A：只平衡有效来源数

该尝试没有拆分内容组件，来源比例较接近70/15/15，但窗口量约为
77.64%/11.49%/10.88%，会使Train、Val和内部开发Test的样本量严重失衡。该版本在
清单阶段即被拒绝，没有作为正式候选训练。

### 7.2 尝试B：只平衡唯一窗口数

该尝试把唯一窗口数严格平衡到70/15/15，所有已审计哈希交集也为0，但正类有效来源数
约为83.4%/8.3%/8.3%。这使Train主要包含短录音，而Val和内部开发Test包含更多长
录音，形成新的时长分布漂移。该错误版本曾完成seed 42训练，其结果为：

| 项目 | 被拒绝结果 |
|---|---:|
| 最佳epoch | 1 |
| 最佳Val-F1 | 0.689790 |
| 对应Val-AUC | 0.821668 |
| 早停epoch | 5 |

这些数值只用于证明分配策略有问题，不属于正式候选结果，不得与历史G7或最终原生
0.5秒v2直接比较。

被拒绝版本的约15 GB缓存、检查点和旧训练日志已经删除，避免被误当成正式结果；当前
仓库只在本文保留其拒绝原因和关键诊断数值。被删除内容不能直接恢复，如确需复核只能
按旧分配器重新生成。

### 7.3 最终原生0.5秒v2：来源数与窗口数联合平衡

最终版本改为：

1. 用seed 42对完整组件做确定性哈希初分；
2. 在不拆组件的前提下进行确定性局部平衡；
3. 同时最小化每类有效录音数和唯一窗口数相对70/15/15目标的误差；
4. 若最大比例误差超过0.1个百分点，清单构造直接失败，禁止训练。

## 10. 结果应如何解释

本次原生0.5秒v2内部指标仍然较高，但不能据此恢复旧的独立测试结论。新协议移除了已
审计到的精确重复输入和类别相关循环补齐；同时，Train、Val和内部Test仍来自同一个
DADS数据池，而且缺少会话、设备、场地和型号元数据。正确解释仍应同时报告：

- segment-level Accuracy、Precision、Recall、Specificity、F1和ROC-AUC；
- source/recording-level mean与max聚合指标；
- Val与内部开发Test的类别数量；
- 固定阈值和阈值来源；
- 清单、审计、缓存、检查点和预测数组SHA256。

即使原生0.5秒v2指标很高，也只能说明“精确内容组件保护的DADS同数据源内部识别”
有效。由于DADS缺少权威的会话、场地、设备、距离和无人机型号元数据，它仍不能证明
跨域泛化。

bash scripts/run_g7_leakage_fixed.sh prepare

# 快速验证清单；不重新读取全部缓存内容
bash scripts/run_g7_leakage_fixed.sh validate

# 验证缓存整体SHA和每条波形哈希映射
bash scripts/run_g7_leakage_fixed.sh validate-full

# GPU单步预检
bash scripts/run_g7_leakage_fixed.sh preflight

## 12. 仍未解决的问题

本轮已经修复的是审计范围内的精确内容跨split交叉、类别相关循环补齐和划分分布漂移。
仍未解决：

- 近重复但哈希不同的声音；
- 同一场景、同一设备或同一录制会话的隐性相关；
- DADS音频与AudioSet预训练语料之间是否存在内容重叠；当前工程尚未建立可用于完整
  比对的AudioSet原始音频哈希清单；
- 跨麦克风、跨距离、跨地点和跨噪声域泛化；
- 新型号无人机上的检测召回；
- 三随机种子的均值与标准差；
- 真正未消费的新采集最终Holdout。

因此，原生0.5秒v2是比历史协议更可信的内部基线，不是“全部泄漏已经消失”的证明，
也不是外部泛化问题的最终答案。
