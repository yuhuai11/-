# 工程目录整理与历史模型归档说明

## 1. 整理目的

本工程在连续实验后形成了多个顶层`artifacts_*`目录，旧基线、失败候选、正式模型
和当前开发产物混在一起，不利于判断：

- 哪个检查点是当前正式模型；
- 哪些模型只是历史对照；
- 哪些候选没有通过门控；
- 哪些目录仍被当前开发链使用；
- 哪些产物可以冷归档但不能删除。

本次整理采用“保留、分类、迁移、更新引用、不删除”的原则。

## 2. 整理后的顶层结构

```text
ABDDV-CRNN/                    历史仓库目录名，兼容保留
├─ README.md
├─ PROJECT_ARCHITECTURE.md
├─ archive/                    # 历史模型与冷数据
├─ artifacts/                  # 共享实验、评估及G8之后阶段产物
├─ artifacts_full/             # 全量DADS共享manifest和缓存
├─ artifacts_g7_panns_pt/      # 当前正式G7
├─ configs/                    # 所有可复现配置
├─ data/                       # 外部开发数据和确认集归档
├─ data_templates/             # 数据模板
├─ date/                       # 原始DADS
├─ docs/                       # 当前方案、结果和说明
├─ logs/                       # 当前及关键正式流程日志
├─ scripts/                    # 运行入口
├─ src/                        # Python实现
└─ tests/                      # 自动测试
```

根目录不再保留11个历史模型产物目录，也不再直接放置论文PDF和文献综述。

## 5. 分类说明

### 5.1 历史基线

CRNN和ResNet10-CBAM基线用于论文复现、训练规模对照和G7提升分析。它们虽然性能不如
当前正式G7，但仍属于必要科学证据，因此放入`baselines/`而不是`failed_candidates/`。

### 5.2 已被替代的阶段冠军

G2曾是开发阶段冠军，后续G3–G6均以G2为保护基线。正式G7完成后，G2不再是当前模型，
但不能标为失败，因此独立放入`superseded_champions/`。

### 5.3 未晋级候选

| 阶段 | 归档原因 |
|---|---|
| G3 | 来源均衡采样导致内部F1明显下降 |
| G4 | 低SNR候选未通过保护门槛 |
| G5 | MFCC-64的Validation/Test F1非劣门失败 |
| G6 | 时序注意力在val_ood门控失败 |
| G7 Scratch | 未替代AudioSet预训练G7，且训练经历GPU故障 |
| G9 | G10/G11冻结评估未允许其整体替代G7 |

这里的“未晋级”表示不满足预注册规则，不表示实验可以删除。

## 9. 使用建议

日常开发优先关注：

```text
artifacts_g7_panns_pt/
artifacts/g14_domain_generalization/
artifacts/g15_constrained_adaptation/
artifacts/g16_multisnr_constrained/
configs/g14_*.yaml
configs/g15_*.yaml
configs/g16_*.yaml
docs/G7模型结果与性能分析报告.md
docs/G17双采样率互补表征与安全后融合方案.md
```

需要复核旧模型时：

1. 先查询`archive/historical_models/MODEL_REGISTRY.csv`；
2. 核对`CHECKSUMS.sha256`；
3. 使用已经更新的新配置路径；
4. 不把归档候选误认为正式模型；
5. 不使用已消费外部测试集重新选择模型。

## 10. 后续可选整理

本次没有移动`configs/`、`scripts/`和`src/`中的历史实现，因为它们体积很小，而且是
复现实验所需入口。后续若继续增长，可采用：

```text
configs/archive/
scripts/archive/
docs/archive/
```

但必须同步修改测试、文档命令和模块路径后再执行，不能只按文件名批量移动。
